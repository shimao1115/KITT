## 3. 县级分包是全国长期架构，而非旧“市州详细包”

- **最小独立内容生产、存储、发布和版本更新单位**为**县级行政单元**：市辖区、县、县级市等，每县可有独立 Fact / Narrative 修订与分发版本。全国共享索引和可选省域通识可独立存在；**市／州为用户默认下载入口**，通过清单汇集实际已发布县包，绝不再另复制一个市州详细正文包。
- 每个县的**现行镇/乡/街道**要有完整调查底账，六类主题逐一扫描；这只是**普查最小粒度**，不是下载包或强制每镇六篇故事。正式故事只对有可靠事实、值得讲且审校完成的内容成篇。
- 六类固定 `NATURE / ENGINEERING / CULTURE / LOCAL_LIFE / HISTORY / TRAVEL`；对象类型不等于讲述角度，旧 `TopicFamily` 不能直接冒充新分类。
- 首批六县级区域：**成都新都区、成都青白江区、德阳广汉市、德阳旌阳区、德阳绵竹市、绵阳安州区**。广汉、绵竹是**县级市**。按当期权威行政区划核镇街名单，不以一条成都—绵阳模拟线路冒充县域普查。
- **全面普查 ≠ 内容完备 ≠ 真机播报覆盖**。分别记录镇街调查率、六类线索扫描率、通过审核的 Claim/故事数、可用且许可合规的空间触发覆盖率。无数据/无高价值故事也允许诚实标缺口。
- **第一份真正制作与发布的详细知识包：成都市新都区**（迁移现有6对象/22条基础事实与按真实审批状态处理的杨慎双篇），**不是先制作整个成都市详细包**。同时创建“成都市”市级聚合目录入口。再用另一个非相邻县级少量合法测试资料验证通用装载，随后开展六区全面调查与内容生产；无需六县全部故事完成才发第一县，也无需等 V0.7 所有增强完成。
- 正式详细工单模板与技术建议参考 [PR #29 的县级采集规范](https://github.com/shimao1115/KITT/pull/29)；该 PR 仍 Draft，**路线决策已经确认不代表工具、Android Schema、仓库或六个县包已经创建**。

## 4. 离线包的发布与分发规则

1. **Fact/Claim 是证据层，Narrative 是人工审阅的成品讲述层**，都只分发合法可再发布的文字/结构化数据。无网使用手机本地中文 TTS，不生成批量 MP3/WAV。
2. **办公室电脑和家庭电脑生产，GitHub Git 保存可公开源文件；GitHub Releases 为正式发布渠道**。计划中的 `KITT-PACKS` 仓库待另行授权创建；不恢复 NAS 或另设服务器。
3. GitHub 直连在中国大陆/安卓车机上不保证可靠，所以**下载与本地文件导入同属 V0.6.1 的首版必备入口**。电脑/U盘只是将**同一官方签名发行包**送到设备，不能成为第二套审批/版本真相源。
4. **默认用户流程**：进入“离线知识管理”→选择**成都市／德阳市／阿坝州**等市州→点击“下载该市州已发布内容”，自动列出并下载**该市州当前真正存在且已正式批准的县级 Fact/Narrative** 与最小共享依赖；**支持展开到区县单独选择**。如果成都市暂时只有新都区发布，按钮仅安装新都区并明确显示“当前仅新都区有已发布资料／成都市未全面覆盖”；对其他县显示未制作／未发布，**不可称“成都市全部知识已就绪”**。并非每县都一定有正式故事，有 Fact 无 Narrative 就显示“仅基础事实”。市州目录为索引/组合，不是另一套物理详细包。
5. **整市州一键操作只是由多个县级安装任务组成**，下载前清楚显示本次实际所含区县、包体积与内容覆盖；允许局部已就绪/部分失败并分别显示真实状态，失败不能损坏原有可用县包；未来发布新增县包**不得未经用户确认自动扩大已下载范围**。下载/本地导入复用**同一信任验证、版本兼容、原子安装及失败回滚**。签名/哈希不能只依赖下载 HTTPS；撤销错误 Claim 只停用精确依赖它的故事，无关内容继续可用。
6. Wi-Fi 自动更新安排到**基础手动分发稳定之后**；行前提醒、下载差分、自动全路线预取和发布镜像以后按真实需求决定。
