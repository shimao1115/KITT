## 1. 给用户的使用体验：离线数据是基础能力，不是技术课

**普通游客看到的是“离线知识”，不需要知道 Fact Pack、Narrative Pack、Git commit、Schema 和 Release。**

- 入口可叫 **“离线知识管理”**：搜索地区，按省份→市／州浏览和一键下载已发布内容，并可展开选择实际存在的区县独立包，查看已装内容、版本/更新日期、大小、空间需求、是否可更新和真实覆盖程度；支持下载、暂停/继续、取消、更新、删除、明确错误提示。
- **市／州一键下载、区县按需选择**：例如点“下载成都市已发布内容”，程序从可信市级目录选取成都市**当前实际已发布**的区县 Fact + Narrative（及必要共享依赖），批量安装；也允许展开仅下载“新都区”。区县两层内容各自独立更新，普通用户不必理解文件结构或填写 API。
- **下载来源范围**：全国基础（真实许可允许的地名/行政身份/空间索引） + 可选省级通识 + **县级详细双包**（市州聚合而非重复存正文）；**县级包不以下载完整省包为先决条件**。有事实引用跨区或省级资料时，解决实际所需最小依赖或将相应故事标为不可用，不静默播放不兼容故事。
- **展示事实与故事的差异**：同一区域可标明**“基础资料已就绪”“有精选讲述”“内容逐步扩充”**；可以显示有来源的对象数、已审稿完整主故事数、关联覆盖的区县/乡镇数与最近更新日期。**“已安装某市州的部分区县”绝不等于“全市每个地方都有完整故事”**。数据计数必须来自实际 manifest，不能捏造比例、星级或百分比。
- **首版手动下载＋本地导入，下一版再支持默认 Wi-Fi 自动更新**：用户明确选择市／州的已发布区县集合或单独区县，能够检查并手动更新；以后启用可关闭的 Wi-Fi 自动更新，使用移动数据须用户明确许可，不暗中下载未选地区，也不从 GPS 隐式推导整条旅程。
- **已安装内容断网持续可用**：有可信 GPS、兼容的文字包和设备的离线中文 TTS，仍能在“离线优先”听完整成品故事；GitHub 或两台生产电脑不可达都不影响已装内容。无 API 不降低正常故事品质。
- **下载和讲述分离**：行驶过程中优先保证定位、已播记录和 TTS，不在前台重复打断播报要求升级；后台行为只在系统允许和合理网络条件下进行。数据更新时不必暂停当前一段已开始的朗读。

### 默认市州下载的真实覆盖原则

- **下载入口 ≠ 文件边界**：市／州是用户操作与目录聚合单位，县级才是文件/版本/审核/更新单位；镇乡街道是知识普查与讲述索引单位，不能按“每镇一个下载包”或强制每镇有故事。
- **第一个生产样板是成都市新都区**，迁移已有 6 个对象 / 22 条基础事实，并单独处理杨慎双篇正式审核状态；同时提供“成都市”聚合目录，**不是把全成都市资料一次性制作完**。
- 市州一键按钮只能组合**当前真正存在、合法发布且兼容的县级包**。界面显示“可下载区县 X / 实际行政区县 Y（以权威现行名录为准）”、已装/未发布/仅事实/有完整故事等不同状态；未拿到可靠分母时不要编造百分比。
- 用户可展开、取消选择部分县，下载前看到实际包含内容和总量；不会因点击市州而自动生成空县包。更新/清理分别对实际安装的县包生效。

## 2. 客户端状态与用户提示（参考成熟离线地图的数据生命周期）

建议状态机（实现细节可迭代，含义要稳定）：

| 可感知状态 | 必须表达的真实含义 | 用户能做什么 |
| --- | --- | --- |
| 未下载 | 尚无适配的本地资料 | 下载或查看需要空间 |
| 等待网络/Wi-Fi | 下载受当前连接/偏好限制 | 允许移动数据或等待 |
| 排队/下载中 | 正在获取部分或全部文件，进度仅基于真实字节/文件 | 暂停、取消；已装旧包继续可用 |
| 已暂停 | 暂时停止传输，数据尚未启用 | 继续或取消 |
| 校验/准备中 | 正在验完整性、发布者、格式、依赖、空间及可用性 | 等待；不可误标“已就绪” |
| 已就绪 | 所有**实际必需的**内容及依赖校验通过且已激活 | 断网讲述、查看版本、删除 |
| 有更新 | 有新兼容版本可下载，**不表示当前版本立即失效** | 查看更新说明，手动更新或等待 Wi-Fi |
| 安装失败/已回退 | 当前更新失败，兼容旧包保持有效 | 重试/查看原因；不清除旧数据 |
| 部分可用/需补充 | 缺讲述、缺依赖、内容过期需重审或可读性受限 | 查看缺少的内容、补装或在可行时继续听有效内容 |
| 不兼容/已停用 | App/Schema/地区/证据撤回或严重安全/授权问题致无法安全启用 | 解释具体原因及可执行恢复方式 |

必须分别识别并显示：无法连接 GitHub（或下载地址）、网络中断/Wi-Fi 限制、空间不足、写入错误、文件格式损坏、校验和/签名失败、缺依赖、包版过高/过低、实际区域无故事、事实被撤回或版权失效。**不要把所有问题统一写成“下载失败”，更不能在失败时删除已安装的兼容旧版本。**

用户不必理解具体错误码，但应该知道**这次做没做成，以及下一步可做什么**。

## 3. 更新机制：小步、低打扰、失败不损坏旧内容

**更新契约（分 V0.6.1 手动阶段与 V0.6.2 自动阶段）**：

1. 在联网时以合理的低频/生命周期契机检查可信**GitHub 发布目录 catalog/manifest**，不能行驶中高频轮询；检查失败不影响已装版本。目录内含地区、Fact/Narrative 版本、Schema、文件大小、依赖、最低 App 兼容性、内容/权利摘要与下载位置。
2. **V0.6.1 先提供手动检查/下载/本地文件导入**；V0.6.2 再加入**仅对已装地区**的可关闭 Wi-Fi 自动更新。下载仅在资源条件合理时执行，不需要长驻服务器；网络和蜂窝偏好要尊重用户。
3. **区别更新种类**：增加故事、增加事实、事实勘误、改进讲述、修正来源/授权、兼容性/格式变化；分别显示简洁人话摘要，例如“新增12篇讲述、纠正3条事实”，数字必须由真实发布数据计算，不能随意写。
4. **第一阶段对小文本包做整包版本替换**，Fact 和 Narrative 分别打包和升级；不把二进制差量算法、全国 CDN、常驻数据库服务当作前置需求。跨包依赖应解析到**可验证的具体 Claim 修订/指纹**，不是“只要县级事实包版本变了，全县故事都作废”。
5. 下载新版到**暂存区**，核查可信发布者、完整性 SHA256、JSON/数据库或容器格式、内容版本、Schema/App 兼容、地区身份、所需基础包、故事所引用 Claims 及权利状态，**全部通过后才原子启用**；失败保留现有完整版本及本地已播数据。
6. 更新过程中/更新失败时旧兼容包继续工作；成功激活后再清理无用旧文件，至少确保有可回滚的恢复机制；**不要强制清理用户未选删除的地区包**。如升级中途磁盘空间不足，拒绝覆盖旧版本并给出空间提示。
7. **没有固定的历史文化知识有效期**：旧地方志可能仍可靠，“有更新”不等于“强制过期”。仅在已知严重事实错误、授权撤回、包不可兼容等情况下停用**真实受影响**的 Claim/故事；无关故事继续可用。离线设备无法即时接收到新撤回信息，不能宣称已经实时纠错，下一次成功校验发布目录时应用更新的撤回/风险信息。
8. **已播记忆与包分发独立**：升级不应让用户以为从未听过旧篇章而反复播报，除非故事确实修订且产品有清晰的重播判定。

**信任边界**：SHA256 验的是文件完整性，**不单独证明发行身份**；真正面向公众自动更新前，应确立可信发布者验证（例如独立公钥/签名或其他等效机制），不要复用 Android APK 私钥，不允许不经审查从任意网址下载并自动启用知识包。此项具体实现需单独工程任务实测。

## 4. 只处理知识，不处理导航

- **借鉴的不是导航算法**：参考的是离线产品的“选地区 → 下载 → 校验 → 使用 → 更新/管理”的体验，以及应用自身对在线/离线来源的明确策略。
- **讲述模式单独存在**：默认“离线优先”直接读已审核 Narrative；“即时优先”由 AI 灵活组织但仍可优先检索本地可信 Fact/Narrative（用户已确定方案 B）。**这项讲述来源设置不等于离线知识包的自动更新开关**。两模式均允许“探索地点”查已安装的本地地区包、看完整文字并主动点击底部播放。
- “即时优先”网络或 AI 不可用时，明确提醒后回退本地成品故事；真实路况/天气/票务应从真正可靠的新鲜来源查询，**在线模型本身不保证实时准确**。
- 事实、讲述、地图数据和未来可能更好的设备 TTS **都是不同资产**：地图地图瓦片、预配音、语音模型、导航业务不混进知识包；中国地图/地理数据仍独立核对许可、精度和合规性。

## 4A. “探索地点”不是“下载知识包”，二者界面职责分开

- **讲述分类与用户兴趣**：首版固定六类，正式故事有一个主类和可选辅类，“多讲/正常/少讲”是后续设置中的柔性选题偏好；**下载与更新不按偏好偷偷删掉用户不常听的类别**。分类在探索地点可作列表筛选，也方便通过真实稿件数检查知识包覆盖。具体规则以[知识内容标准 V2.4](KITT_KNOWLEDGE_STANDARD.md)为准。
- **“离线知识管理”**负责哪些地区已安装、缺哪些资料、更新/容量/删除；**“探索地点”**负责从已安装事实/讲述索引里**选择地区和主题并阅读故事**，用户可搜索并非 GPS 所在地的马尔康市等。
- 点击主题时，默认打开已审核 Narrative 的**完整文字正文**，页面底部的**播放按钮**才使用手机本地 TTS 朗读同一篇文字；没有联网、没有云模型也能完成这一链。有 Fact 无 Narrative 则提示“仅基础事实”，没离线 TTS 也应保留文字阅读。
- 本地缺地区时可根据用户意图提示“下载离线内容”，或者在真实联网/可用模型能力下做**临时在线探查**；临时内容与正式审核素材严格标明。不能因为用户在探索地点输入马尔康，就覆盖真实 GPS/旅程当前位置。
- 详细行为以 [知识内容标准 V2.4](KITT_KNOWLEDGE_STANDARD.md) 中“探索地点”章节为准；现有 code14 还没有该页面，不得当作已实现功能。

## 5. 中国大陆 GitHub 可达性：正式存储唯一，但要有本地导入

- 正式源、版本历史与下载附件仍**只以 GitHub 为分发的唯一权威**，不自建 NAS/家庭服务器、不增加第二套“官方发布中心”。
- 考虑用户可能访问 GitHub Releases 不稳定，**V0.6.1 首版即提供“从手机本地文件导入已签名知识包”**：用户在办公室/家庭电脑或其他有网络设备获取**同一正式 Release**，经合规文件传输到手机，KITT 依照相同签名、摘要、版本和依赖规则验证后导入。导入仅是另一种**运输方式**，不是另开内容真相源。
- **P0 必做实际兼容/可达性验收**：在不同网络（如成都电信宽带及常用手机移动网络）、无代理真实用户条件下检查 GitHub Release 下载可达率、失败恢复、耗时和数据完整性；测不到则坦诚标为待验收，不能承诺所有大陆用户直连稳定。**本地导入机制列 V0.6.1/P0**，是 GitHub 不可达时的首版必备兜底。
- 无 Wi-Fi 时用户可明确选择移动网络，不能偷偷绕过蜂窝流量偏好；不在后台持续多次失败重试耗电。

## 6. 后续功能优先级与不做范围

### P0：首个完整地区包管理版本应实现

- **默认市／州列表和搜索，市／州一键下载**其目前实际已发布的县包；展开可选区县、查看真实下载状态/内容覆盖、大小/空间、下载/暂停/继续/取消/删除；不能用县包部分安装冒充全市覆盖。
- **市／州目录只是一组县包索引**（包含具体已发布县级单元与版本），一键操作逐县解析 Fact + Narrative + 最小必要共享数据；例如只有新都区正式发布时，“下载成都市”实际仅安装新都区，并明确标“成都市目前只提供新都区内容，其他区县未覆盖”。不制作重复的成都市正文包。
- **V0.6.1 同版支持市州聚合的一键 GitHub Release 下载、可选单县下载与本地文件导入**；在线/本地共同使用逐县签名/版本/依赖/原子安装/回滚校验。市州一键下载前显示**实际可用区县清单、总大小和真实覆盖**，用户确认后执行；某个县安装失败时其旧数据不变并如实显示部分成功，不把整个城市伪称已完成。
- 暂存/校验/原子启用/失败回滚、格式/权限/证据引用/签名有效性验证，离线可继续使用旧版；只停用真实失效的故事。
- **普通无 API 用户断网完整讲述的黄金路径**；离线优先（默认）与即时优先（可选）是独立于包更新开关的内容选择策略。可视化覆盖信息不能夸大事实与完整故事范围。
- 真实手机、真实网络环境验证下载、安装、错误与升级；没有实际测试不标 PASS。

### P1：手动下载/导入稳定后增加（建议 V0.6.2 及以后）

- **行前准备**：用户主动输入/确认目的地或途经市州时，提示“此地区尚无离线知识/有新版”，允许一键预下载；不依据常驻定位悄悄跟踪或批量下载。
- **Wi-Fi 自动更新**：默认仅适用于用户**已经选择并安装的县包**，用户可关闭；低频检查、出错不干扰讲述。若原先按市州下载安装，后来新发布了别的县包，不能未经确认就扩大自动下载范围。
- 可选的下载完整性/存储视图、精细化管理和自愿清理提示；**不默认自动删除**长期不用的地区数据。

### P2：有真实规模/成本证据才考虑

- 只传变化部分的增量/差分包、按路线批量预取与高级缓存策略、下载体验的复杂优化。
- 大规模分发后如 GitHub 的可用性或限额确实不适合，再由用户决定新方案；**本规范不预设 CDN、NAS、第三方云盘或多发布源**。
