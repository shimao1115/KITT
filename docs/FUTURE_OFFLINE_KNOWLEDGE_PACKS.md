## 1. 产品价值与边界

**KITT 是 AI 旅行助手，不是研究助手或历史专用讲解员。** 自然山河、地理生态、桥隧与交通工程、民族人文、地方产业物产、历史人物、旅行知识都可作为旅途主题。面对路过的普通游客，先介绍背景，讲一个有意思的故事，想听深入再展开。证据深但讲述浅显；没可靠、有趣、适用的内容时安静。

**无 API 基础体验**：不配置云端大模型和本地 LLM，也能以可信位置和已下载的成品文字讲述获得自然、完整的离线介绍；手机使用自己安装的中文 TTS 朗读。联网且用户接入模型时，再由 AI 使用本地事实包支持自由问答、图片理解和资料拓展；联网只是可增强、不是讲述基本前提。

**不制备离线音频知识包**。GitHub 只保存经过合法处理的文字/结构化知识；讲述质量来自精心编辑文字，音色与 TTS 引擎独立升级，不上传大批 MP3/WAV，也不在知识包中捆绑模型和版权受限的配音。

## 2. 两个正交维度：地域与内容

| 地域层次（用于分发） | 事实包 Fact Pack | 讲述包 Narrative Pack |
| --- | --- | --- |
| **全国基础** | 行政/地名与可靠空间索引、公共稳定事实、跨区共享对象；地理数据必须有可再分发许可 | 可选的全国跨区域主题讲述，不要求全国只有一篇总导游词 |
| **省级通识（可选）** | 跨市州山川、自然生态、地域文化、工程和生活背景 | 省域和跨地区关系的成品故事 |
| **市州/城市详细** | 区县→镇乡街道→人物、建筑、桥梁、河流、物产等对象，可靠原子 Claim 与来源 | 按对象/沿途单元组织的主故事、延伸篇及关联篇 |

- **城市包只强制依赖必要的全国基础资料**，不强制整个省包；如果某个故事必须引用省包中特定 Claim，先解决该最小依赖或该篇暂不可用，不留悬空引用。
- “区县作大背景、乡镇街道为沿途讲述组织单元”仍成立，**真实性建立在可核查行政/空间数据之上**。乡镇没有真实几何不能假装准确识镇；“这个人属于此地”不等于“车窗里看见此人遗迹”。
- **Overview/Topic 保留**：作为地区索引和对象专题视图，不再代表独立的物理存储包，也不意味着只能把两个事实片段直接拼成介绍。
- **两个内容包逻辑独立、版本可独立更新**，用户端可用一个“下载某城市完整内容”入口自动安装匹配的两层与基础依赖。不强迫游客理解 Fact/Narrative 技术名词。

## 3. 事实包和讲述包的分工

**Fact Pack：简练但充实。** 一条 Claim = 一个可验证说法；记录真实出处、版本/页码或网页位置、时间与空间适用性、证据等级、关系/冲突、许可和更新情况。人物不应仅有姓名与官职；杨慎的代表性作品、重大人生转折、文学影响及新都关系都属于合理查证目标。没有来源则不编造。

**Narrative Pack：精心准备的成品中文故事。** 一段主故事应在用户完全不追问时也有背景、亮点和结束；后续有更多经过核实的内容时准备延伸及关联篇。单篇是预写文字，不代表整条旅程固定播放顺序；本地 Director 按地点、已播、用户偏好及驾驶场景决定选择/重播/安静，而不每次生成新的作文。讲述稿须记录 `narrative_id`、引用的 `claim_id + 有效修订/指纹`、关联区域、估计时长和审校情况。

**事实更正影响准确范围**：一处 Claim 被撤销或修订时，仅需追踪真正依赖它的故事重新核验；无关主题的新事实不能让整个城市讲述包过期。打包/校验时检测故事需要的真实 Fact 数据，不仅粗糙比较整包版本号。

**档案与时效分开**：旧地方志可有效记录历史，却不能证明今天道路开放；稳定文物/工程背景可以离线，临时票价/营业、路况、天气、当日活动须实时查询或直说无法确认。经许可的原始文档仅留受控研究端，不在公开 Git 镜像书籍、文章、影像。

## 4. 生产端：模型可换，证据不可省

用 GitHub Issue 规定地域/对象和交付范围，多个 AI 可以扮演 Scout/Extractor/Verifier/Story Writer/Story Reviewer/Builder。程序根据证据与审核状态生成 Fact，讲述只能引用已审稿 Claim；独立 Reviewer 重新核查原始资料，不把第二个模型复述同一来源当“第二条证据”。人的最终验收集中在争议/授权、完整主故事与真人试听。

**办公室电脑＋家庭电脑负责生产；GitHub 负责唯一正式存储/交接/分发。** 资料调查、不同 AI 协作、核验、成品故事写作与打包只在这两台工作电脑执行。来源台账、事实和故事的可公开文字源及构建工具交给计划中的 `KITT-PACKS` Git；成品经审核后由 GitHub Releases 分发。**不再配置 NAS、家庭服务器或 NAS 备份/分发路线。** 受限制的原始材料仅在有许可的电脑工作区处理，不能因 GitHub 是中心便公开转载。手机已装包后完全独立使用。详细交接/发行标准见 [工厂协议 V2.3](KITT_KNOWLEDGE_FACTORY.md)。

## 5. 手机离线/联网选题

| 网络 | 是否有已配置、可用的大模型 | 行为 |
| --- | --- | --- |
| 无网 | 无 AI | GPS → 可用地区 → 查兼容讲述包 → Director 选已审稿主故事 → 本地中文 TTS；预制延伸/重播/静音可用 |
| 有网 | 无 AI | 仍直接讲本地好故事；网络只用于包获取/升级及其它真实独立在线能力 |
| 无网 | 有 AI 配置 | 本地故事正常播报，停止云端研究/推理请求；不拿过期事实冒充实时 |
| 有网 | AI 可用 | 默认可以直接使用成品故事，也可在需要时调用事实包帮助 AI 追问、图片理解、联网补缺/时效查询 |

**语音能力独立**：手机需实际安装可离线运行的中文 TTS 才可朗读；它可以升级为以后更好听的本地音色/语音模型。没有安装时如实提示，不要静默失败。离线词稿不等于离线自由问答；不知道的开放问题应承认限制。

**降级不是假验收**：如果当地还没有成品讲述包，可在安全/合规的前提下提供简短**已审校事实**或安静，但不能把旧 code14 的两条拼接当作“高质量完整版故事”PASS。用户没有输入 API 不能影响已装好地区故事的播放。

## 6. 讲述模式建议：离线优先（默认）/即时优先

**默认离线优先，用户可主动选择即时优先；用户已选择方案 B：无论哪一种模式，AI 回答地方问题时都可以优先检索可信本地事实。** 建议设置页简单二档，具体布局另行验收。

- **离线优先**：普通沿途播报选择已下载、已审稿的 Narrative Pack 成品；若用户要求实时天气、道路临时状况、开放式问题等，且网络与 AI 实际可用，**只将该单次问题路由至在线能力**，答复后回原默认；稳定资料无需重复调 AI。
- **即时优先**：正常讲述由在线 AI 即时研究/组织，**先按地方对象与问题检索少量本地 Fact/Narrative 作为证据**，必要时联网补充与核实；不是永远忽略本地包。仍须真实 GPS、话题/已播/TTS、安全和时效门禁。
- **无法在线/未配置 API**：提示在线生成不可用，然后回退已安装的本地优质故事；区分“AI 讲述失败回退”与“AI 实际实时核验”。默认模式不强迫 API。
- **最新事实核验**：即时优先不自动代表最新，天气、路况、票务等必须有实际上可用的权威实时检索/数据渠道，否则如实说无法确认。可能产生模型调用成本，应在设置说明，不无声消耗。
- **当前施工边界**：V0.4.0 尚未有完整 Narrative Pack 选择器，更没有这组双模式 UI；在用户授权下一版之前只讨论并保存规范。

## 6A. 探索地点：文字阅读主入口，按需播放

- 产品新增第三种交互：**听沿途（自动播报） / 问 AI（可先读本地事实） / 探索地点（主动看）**。正式按钮名称就是**“探索地点”**，不是仅限 GPS 当前位置的“探查本地”。
- 打开后默认可看当前位置，也可手动搜索任意远处城市/地区，例如人在新都搜索马尔康。优先列手机已下载地区包中的**真实可用主题**（人物/山河/园林/工程/地方生活），手机以可点选分类列表为主，大屏可用表格。
- **点主题 → 完整审核讲述稿正文**，默认**只显示文字，不自动播放**。下方提供**“播放”按钮**，主动点击时手机本地中文 TTS 朗读**同一篇文字**；文字仍可读。将来可有暂停/停止/延伸篇，不要求内置新语音模型或音频包。只有 Fact 没有 Narrative 时需标“仅有基础事实”，不能假装完整故事。
- 查询地区有包直接浏览；无包但实际有网络、用户配置可用 AI 且能查询资料时，提供**明确标注“在线临时探查”**的主题/回答及实际来源；两者都无时告知缺资料，必要时引导下载。临时结果不能偷偷写入经过审校的正式 Fact/Narrative。
- 浏览异地**不变更 GPS 判断/旅程当前区域**，驾驶员在行驶中不被引导看长文，乘客或停车后使用。模式“即时优先”也不禁用本地探索；讲述偏好和查看文件是不同事情。
- 下一阶段可先用真实新都条目验证“列主题→看全文→底部播放→搜索另一个地区”的最小路径，避免先建复杂 RAG/向量检索体系。**目前 APK 尚无本功能**。

## 7. 离线知识下载、更新与清理（借鉴成熟地图模式）

**详细规范的唯一入口**：[KITT 离线知识包管理与更新标准 V1.0](KITT_OFFLINE_PACK_MANAGEMENT.md)。借鉴高德、百度、Apple 地图、Google Maps、OsmAnd 的离线资源管理体验，**不照搬导航算法或地图瓦片系统**；下方是已批准的产品优先级摘要，不再另行维护冲突的下载规则。

- **P0 地区一键准备**：按国家/省/城市组织，用户选择地区后自动检查必要全国基础数据、完整 Fact + Narrative 双层版本、实际跨包 Claim 依赖；城市无需强制完整省包。显示真实文件大小、已就绪/部分可用、实际覆盖对象和已审稿主故事数量，不把“城市已装”说成“每个镇街都有故事”。
- **P0 默认 Wi-Fi 自动更新已装内容（可关闭）**：有网时低频检查 GitHub 发布目录，下载新版依旧尊重 Wi-Fi/用户许可移动数据偏好；不暗中扩大全国下载，也不因更新打断驾驶讲述。显示新增故事、勘误和真实更新时间等内容变更摘要。
- **P0 可靠安装**：下载/暂停/继续/取消/删除、网络/权限/空间/签名/格式/依赖各自明确状态；新版先暂存，核对发行者、哈希、App Schema、Fact 引用及权限后再原子替换。**失败继续用旧包，不清空已播记忆；成功后安全清理旧文件**。
- **P0 不强制知识按日期过期**：旧稳定历史资料可继续用；有更新不等于旧版不可用。仅依据实际证据撤回、严重事实错误、许可失效或兼容问题，限制受影响故事，未受影响篇章可继续用。
- **P1 行前准备和本地导入**：用户明确目的地/途经地区时推荐缺少的包或更新；中国大陆 GitHub Release 下载速度/可达性需实测，无代理用户不一定能正常下载；后续允许从电脑传来的**同一正式 Release 文件**验签导入手机，**不设第二官方分发中心**。
- **P2 有数据证明需要再做**：差分增量、复杂自动预取、海量后台调度；以纯文字包为主，早期完整包替换往往更简单，先测真实尺寸与耗时再扩张。
- **与讲述模式独立**：离线优先（默认）与即时优先是“内容来源”设置；Wi-Fi 自动更新是“资源维护”设置，不能合并成一个按钮。用户不配置大模型，也能用已安装的完整故事+本地中文 TTS。
- **GitHub 唯一正式发布**：计划中的 `KITT-PACKS` Git 储存可审查源文件，GitHub Releases 发文字压缩内容/真实版本清单，签名与完整性要求见管理规范；不制音频/地图知识包、不恢复 NAS。**当前未建仓、未上线下载器**。

## 8. 推进顺序与真实 Gate

**已发生**：V0.4.0/code14 新都 6 对象/22 条、真实离线杨升庵事实播报成功，用户明确指出故事深度不够；这不是两层成品故事机制已经完成。

**下一阶段建议的唯一最小产品实验（未来需授权）**：取新都事实，补齐杨慎流放、学术与文学成就、《临江仙》相关真实出处，完成一篇约 1–2 分钟的**主故事示例**及合理的延伸篇（时间是编辑建议，不是所有主题的强制配额）；另一 AI 逐句回查，真人试听；手机在真实无网、无 API、有新鲜定位时整篇播放且能再讲/重播/静音。还要能在线使用 Fact 作为 AI 背景、离线无法任意问答时诚实提示。

**知识工厂独立复现**：另一个 AI/电脑只读 Git Issue 和已合并的事实/讲述源文件即可复现包，不依赖前一个人的聊天。Claim 更正只影响关联 Narrative。实测包容量、加载时长、听感与事实准确性、依赖/失效策略，再考虑扩其他成都区县、四川、全国。

**地图是后续独立候选**：MapLibre/地图瓦片与事实/讲述包不是一个内容层。地图许可、境内测绘合规、坐标与地图数据取得可行性要分别调查；不以地图引擎“开源”直接推出地图内容可分发。

**Stop Rule**：用户未另外批准时，不扩工作到新地区、地图、批量抓取、GitHub Release 下载平台、Android 新版本或语音模型安装器；也不回溯修改 #20 原工程授权。旧单层事实包、NAS 中心/备份路线、必须云端 AI 才能讲述、整趟唯一固定脚本等旧设计自本版起不再有效。
