## 1. 产品身份

**产品名：沿途**
**仓库代号：KITT**
**定位：一个会读懂你正在经过的地方的 AI 副驾驶**
**Slogan：读懂沿途的世界**

核心体验：

> **读懂沿途的世界；你开口时，它听你的。**

它不是导游 App、百科 App 或导航 App。它的灵魂是：在移动中的真实土地上，知道什么时候值得开口，
把此刻真正值得听的东西用最合适的方式讲出来——可以是一段历史、一个物件、一个人、一种吃食、一处工程，
也可以只是一句“刚过了什么”。没有值得说的时候就安静。

长期可以成长为更广义的旅途 AI 同伴，但 V0 只证明“位置感知 + 自动导演 + 自然接管”的主链。

---

## 2. V0 唯一成功标准

模拟一辆车以约 **80 km/h 从成都驶向绵阳**：

- 用户不需要维护路线；
- KITT 能随着位置变化理解当前现场；
- 只在真正值得打破安静时主动讲；
- 一段讲一个值得讲的对象或一段有意思的线索，不套用固定叙述模板；
- 用户可以随时打断、追问、要求深入、改变偏好或让它安静；
- AI 可以在关键不确定处主动问用户，而不是长期猜；
- 不值得讲时保持安静；
- 断网、超时、查证失败不会把驾驶体验变成“错误处理现场”。

真正的主观 PASS：

> 跑完整段模拟后，能感觉副驾驶旁边坐着一个懂山河、懂分寸、也听得懂人的 AI。

## 3. 产品哲学

### 3.1 AI Native

提供目标、上下文、边界和验收，让 AI 自主判断路径。不要把“发现桥→讲桥”“进入县城→讲县史”写成规则引擎。

### 3.2 本地确定 → 问用户 → AI 推理

这是 V0 降复杂度与省额度的总原则。

例如：
- 目的地：直接问“今天准备去哪儿？”
- 明显计划变化：问“计划变了吗？”
- 用户想听工程还是历史：必要时可以问。
- GPS、速度、10 分钟计时：本地代码处理。
- 什么时候值得讲、讲什么、怎么解释：交给 AI。

### 3.3 传感器高频，AI 低频

GPS 可以高频更新，但没有新信息就不调用 AI。
一次 AI 醒来尽量完成：判断 → 选题 → 必要查证 → 生成 → memory update。

### 3.4 安静是合法输出，不是默认礼貌

“没有值得说的内容”不是失败；但把“安静永远更安全”当成挡箭牌也不是美德。
经过一连串有历史、有去处、有人物的乡镇却几乎全程沉默，同样是失败。
自动模式只讲此刻值得打破安静的内容；进入新的镇乡街道章节时，先看过本地素材架，再决定讲哪一条或不说。

### 3.5 User intent wins; stale content dies

用户最新、明确的意图最高优先。
过时的旁白、已经错过现场的 PREPARE、被用户主动切断的内容，不因为已经生成就补播。

### 3.6 搜索负责证明，旁白负责解释

联网搜索是事实底稿，不是旁白素材倾倒器。
自动模式负责讲懂；用户追问时再讲深。

## 4. 典型旅程

### 4.1 开始

用户点巨大按钮 **「开始沿途」**。

完成定位后，AI 用语音问一次：

> “今天准备去哪儿？”

用户可以说：
- “马尔康。”
- “去绵阳。”
- “先往西走，还没定。”
- “不用管目的地。”

目的地是 **旅程意图，不是精确路线**。

确认后只做轻反馈，例如：

> “好。路上看到值得讲的，我再跟你说。”

不要立刻播百科式开场。

### 4.2 自动模式

App 持续感知本地位置。
只有出现足够新的现场变化或到达必要的导演检查点时才唤醒 AI。

AI 可返回：
- SILENT
- SPEAK_NOW
- PREPARE
- ASK_USER

### 4.3 用户主动接管

主界面最大按钮：**「说点什么」**。

单击后：
1. 当前 TTS 立即停止；
2. 开始一次语音监听；
3. 用户说完自动结束；
4. 语音转文字；
5. 同一个 AI 结合现场回答；
6. 回答结束后进入短暂软冷却，再自然回到自动模式。

不做“按住说”。

### 4.4 AI 主动提问

当“问一句”明显比猜测更可靠、更便宜时，AI 可以返回 ASK_USER。

AI 用 TTS 直接问，然后临时自动开启一次监听。
用户回答则继续；无回答则放弃，不重复催问，不做问卷式连续追问。

### 4.5 安静模式

点 **「安静一会儿」**：
- 默认 10 分钟；
- 屏幕切换为巨大的 **「结束安静」** 按钮；
- 显示剩余时间；
- 用户可随时提前恢复；
- 10 分钟到期只恢复“允许导演工作”，绝不立刻强行说话；
- 静默期间已错过的 PREPARE 直接作废。

自然语言可以覆盖默认：
- “安静半小时。”
- “安静一个小时。”
- “先别讲，等我叫你。”

### 4.6 跳过

**「跳过」**：
- 立即停止当前旁白；
- 短时间内避免重复当前具体主题；
- 不自动推断为长期偏好。

一次跳过 ≠ “用户不喜欢历史/宗教/工程”。

### 4.7 再讲一点

“再讲一点”不是复述和机械续稿，而是：
- 围绕当前主题深入一层；
- 选择刚才未讲、但最有解释价值的新角度；
- 不凑时长；
- 若已经没有新的价值，可以自然收住或给出一个真正不同的深入方向。

### 4.8 结束

用户明确点 **「结束旅程」**：
- 停止旅程与前台定位服务；
- 清除当前 PREPARE 和 runtime 状态；
- 生成轻量本地纪要；
- 显示简短评分表。

如果 App 被杀死后发现有未结束旅程：
> “继续刚才的旅程？”
> [继续] [结束]

不要用停车时长擅自判定旅程结束。

## 5. 自动导演的内容方法

### 5.1 内容层给素材，Director 决定怎么说

旅程的自然节奏是：

> **移动 → 经过 → 有东西可讲 → 选择怎么讲 → 停**

没有规定的旁白模板。不要求从眼前切入，不要求先抛一个问题，不要求解释一层，
不要求落回“这片土地”，也不要求以一个道理或升华收尾。

形式按素材本身选择：简短介绍、历史或考古故事、以一件器物或一个人为主线、时间线、对比、
机制解释、地名掌故、工程说明、一句“刚过了什么”的随手指点，或者重大节点上较长的一段讲述。

### 5.2 本地素材架与选题原则

进入一个新的区县或镇／乡／街道，内容层交出的是一整面**本地素材架**，而不是一篇作文提纲：

- 地方史与建置变迁、古镇老街与传统聚落；
- 各级文物保护单位、历史建筑、遗址与考古发现、博物馆；
- 寺庙与地方信仰、风景名胜与自然遗产；
- 文学艺术与地方人物、传说轶闻与有依据的趣闻；
- 非遗与民间工艺、民俗节庆与集市、方言与地名由来；
- 山川水系地貌、桥隧水利铁路等工程、地方道路与交通；
- 特产饮食、农业工业与贸易、街巷与当代生活；
- 以及任何 AI 自己发现、有依据且真正有趣的线索。

这份清单是**开放**的：素材映射不到现有类别时照样讲（标注 `OTHER`），类别不等于允许范围。
不要求每个类别都讲一条，不规定历史→文化→地理→特产的顺序，
不要求标准化的“本区概况”开场，也不要求以关于土地、认同或现代化的结论收尾。

参考但不机械轮换：
- 大：尺度、格局、结构
- 美：真正可感知的视觉/空间关系
- 奇：反直觉、少见、值得好奇
- 变：地形、道路、聚落、产业、时代变化

“地形 → 道路 → 聚落 → 历史/人的生活”可以是一个很好用的视角，但只是众多视角之一。
不按知识类别轮播，也不凑篇数。

### 5.3 自然地理

自然地理是底层解释，不要一路重复“山高谷深”。
相似景观只有出现新的机制、尺度、关系或变化时才值得再次进入。

### 5.4 道路与工程

普通桥隧服务于“人如何穿过这种地形”的解释，不堆参数。

重大代表性工程可以临时成为主角，例如特大桥、代表性长隧道、重大垭口通道：
- 极端问题是什么；
- 工程怎样解决；
- 真正有解释力的关键规格/纪录（必须核验）；
- 它如何改变区域连接。

重大节点允许比普通旁白更长。

### 5.5 聚落与城市

进入一个新的镇／乡／街道本身就是一次讲述机会：先看过本地素材架，再决定讲什么。
“到了一个城市”不等于必须念一段行政区划简介，但也不是拒绝开口的理由。
可用的角度包括：
- 为什么长在这里；
- 为什么长成这种形态；
- 新旧变化；
- 地形、道路、产业如何塑造它；
- 也完全可以选择这里的一条老街、一座桥、一种吃食或一个人名。

### 5.6 历史

历史可以独立成段，不必每次都用来“解释眼前的空间”。
好用的切入仍然包括：
- 为什么路/城/关口在这里；
- 为什么生活与建筑形成这样；
- 什么历史痕迹仍然与眼前有关。

不要随机讲名人年表。历史是山河的时间维度，也是素材架上的正当一等内容。

### 5.7 民族、宗教与文化

从可见的生活、建筑、空间和习惯切入。
避免猎奇、刻板化、把当代人当作“活化石”。
当代生活本身也是文化的一部分。

### 5.8 文风

> **先准确，再好听；先具体，再抒情。**

避免：
- “群山诉说千年故事”
- “岁月留下痕迹”
- “人与自然和谐共生”
- 强行宏大升华
- 教师式总结
- “接下来我们将……”

文学感只能从具体事实中自然长出来。

## 6. 旁白长度与节奏

长度由素材本身决定，不按字数交差，也不要求每一段都收成一个“认知闭环”。

- 普通自动旁白：约 1–2 分钟
- 值得展开：约 2–3 分钟
- 重大节点（重要遗址、博物馆、工程、地理分界）：可以更长，允许讲透
- 简单主题：40–90 秒甚至几句话也可以

硬原则：

> **不凑长度、不注水、不为收尾而升华；但也别为了省事把值得讲透的东西压成一句。**

两段自动旁白之间采用 **软冷却**：
- 刚讲完时，再次开口门槛很高；
- 随时间和距离增加，门槛自然下降；
- 极强时效现场可打破普通冷却；
- 不写死“每 N 分钟必须说一次”。

用户主动对话不受冷却约束。
主动回答结束后有短暂“对话余韵期”，自动导演先退后。

## 7. 事实与搜索

三级事实策略：

### A. 稳定、通用、低风险机制
高置信时可直接解释。

### B. 具体当地事实
每个新章节必须先搜索并形成 Local Dossier；没有可靠 dossier 依据的主动当地问题也先查，例如：
- 河名、桥名、寺庙年代
- 古道是否经过
- 某工程为什么形成
- 当地文化具体事实

### C. 数字、纪录、当前状态
原则上必须查：
- 长度、高度、年代
- “第一/最大/最高”
- 当前封路
- 当前天气
- 当前开放状态

规则：

> **查不到就删掉那个具体事实，不要猜。**

如果来不及核验而现场将错过，宁可沉默。

搜索结果只提取当前核心问题真正需要的少量事实。普通主题常常 2–4 个事实点就够。

## 8. 位置、目的地与地图

### 8.1 硬依赖

**手机 GPS 是唯一硬依赖的位置来源。**

至少使用：
- lat/lon
- speed
- bearing
- altitude（可得时）
- 短期变化趋势

### 8.2 目的地靠问

启动时问用户目的地。
计划发生明显变化而又值得确认时，可以再问。

核心原则：

> **不要为了让 AI“猜得像导航”而建设导航能力；目的地问用户，实际走向看 GPS。**

### 8.3 地图/高德降级为可选增强

如果高德或其他地图接口很容易提供：
- 当前道路
- 行政区
- 少量附近/前方可靠节点
则加入 Context Card。

拿不到就留空，不阻塞 V0，不为此建设复杂路线预测。

## 9. PREPARE

PREPARE 用于少数“错过现场就明显减值”的节点。

它是 **一次性的现场预约，不是内容缓存**。

规则：
- 同时最多一个；
- 必须绑定明确现场目标；
- 目标仍在前方才保留；
- 已经过、明显偏离、目的地变化导致无关、被更重要节点替代 → 立即删除；
- 用户对话期间可以暂存，但恢复时必须重新确认是否仍有效；
- 安静模式中经过则直接作废；
- 不补播“刚才经过的……”

不要让 AI 精确输出“87 秒后播放”。实际位置决定成熟时机。

## 10. 用户可感知状态

正式产品只保留 5 个核心状态：

1. **未开始**
2. **读懂沿途中**
3. **正在讲述**
4. **正在听**
5. **安静模式**

PREPARE、搜索中、模型思考中属于内部事件，不制造额外用户状态。

## 11. 页面

正式 V0 只有两个主要页面。

### 11.1 主驾驶页

原则：像驾驶模式，不像旅游 App。

顶部：
- 当前区域/道路（可得时）
- 当前状态

中间：
- 当前主题
- 无讲话时保持空旷
- 不显示需要驾驶员阅读的长全文

底部固定大操作：
- 最大按钮：**说点什么**
- **跳过**
- **安静一会儿**

硬规则：
- 不滚动；
- 核心按钮位置固定；
- 大触控目标；
- 不用小图标作为唯一入口；
- 不把关键操作藏进菜单；
- 信息宁少勿多；
- 任何核心操作尽量一次点击完成。

安静模式：
- 剩余时间
- 巨大 **「结束安静」**

### 11.2 旅程结束页

包含：
- 轻量旅程纪要
- 简短 1–5 分评分
- 可选自然语言意见

建议评分项不超过 5 个：
- 内容值得听吗？
- 开口时机合适吗？
- 长短合适吗？
- 讲得清楚/可信吗？
- 整体体验怎么样？

V0 不建设行为分析平台。

## 12. 首次体验与权限

不要传统 onboarding 多页教程。

首次：
1. AI Provider 登录/配置（按实际技术路径）
2. 主界面
3. 点“开始沿途”时才申请定位
4. 第一次点“说点什么”时才申请麦克风
5. 通知权限按旅程启动场景自然申请

一句提示足够：

> **开车上路后点一下开始。其余的，跟它说就行。**

V0 权限最小化：
- 精确位置
- 通知（需要时）
- 麦克风（按需）
- Internet manifest 权限

不申请相机、通讯录、短信、存储等无关权限。

---

## 13. 屏幕、后台与通知

- 主驾驶页在前台时可保持常亮；
- 用户主动锁屏/切后台则尊重用户；
- 旅程继续运行；
- 不因为旁白自动点亮屏幕；
- 显示跟随 Android 系统昼夜模式；
- 锁屏时减少需要即时回答的主动提问。

前台服务通知只做轻量后台控制：
- 安静 10 分钟 / 结束安静
- 结束旅程

不把通知栏做成第二套完整 UI。
不弹横幅、不震动、不为每段旁白刷新骚扰。

---

## 14. 声音

V0：
- Android 本地/系统 TTS
- Android 可用的按需语音识别
- 不做常驻麦克风
- 不做唤醒词
- 不做实时全双工语音
- 不做车机音乐协调或 audio ducking
- 音乐由车机播放，用户自行处理两边音量

TTS 应以完整句子/短段进入队列，不按 token 碎片播。

语音识别：
- 单击开始
- 用户说完自动结束
- 明显没听清则简短提示再说一次
- 不要求用户编辑识别文本
- 原始录音默认不长期保存

---

## 15. 本地状态与持久化

V0 不上复杂数据库。

优先：
- DataStore：少量设置、当前状态
- 小型 JSON：旅程纪要、必要 runtime 恢复数据

运行态：
- 最近短期轨迹摘要
- 最近主题
- Session Instructions
- 一个 PREPARE
- 静默状态
- 目的地意图

旅程结束后保留轻量纪要。

默认不长期保存：
- 每秒 GPS 点
- 全量模型请求/响应
- 完整旁白历史
- 原始录音
- 完整主动对话
- 搜索结果历史

产品自己的旅程纪要 ≠ 用户的 GitHub Memory Hub。
V0 不自动写长期记忆。

---

## 16. 故障体验

总原则：

> **故障不应成为驾驶事件。**

自动模式：
- AI 超时/网络失败 → 静默降级
- 不弹复杂错误
- 不重试风暴
- 下一个真正新事件再尝试

主动模式：
- 明确请求失败 → 一句话告知
- 瞬时错误最多自动重试一次（如果实现非常简单）

查证失败：
- 能安全删掉具体数字后继续解释 → 继续
- 核心事实都不确定 → 不讲/说明暂时没查准

已成功 PREPARE 且本地已有文本时，断网不妨碍本地 TTS；但不得用旧内容冒充新现场。

---

## 17. 设置

正式设置保持极简，只放系统级/账号级配置：

- AI Provider / 登录状态
- 模型（Provider 支持时）
- 思考强度（模型支持时）
- TTS 语速
- 通知状态
- 关于/版本

模型不要硬编码在业务逻辑。
可用模型列表能动态读取则动态读取；做不到就以 Provider Adapter 能力为准。

不放：
- 历史/地理/工程权重
- 自动旁白间隔
- 讲解长度
- 搜索深度
- 路线偏好
- 复杂用户画像

能自然语言临时调整的，不做设置项。

---

## 18. 模拟驾驶

模拟模式是 V0 必做的开发工具，但不是正式用户功能。

原则：

> **只替换 Location Source，后面整条生产链保持一致。**

正式：
`Real GPS → Context → Director → Search → Voice → UI`

模拟：
`Simulated GPS → Context → Director → Search → Voice → UI`

第一条验收路线：
- 成都 → 绵阳
- 约 80 km/h

用户可后续提供一张高德路线截图，作为一次性路线制作参考。
如果截图尚不存在，不得阻塞施工：先建立可替换 fixture 和粗粒度测试轨迹，明确标注“非导航级”，待截图到位再替换。

不要为模拟器接生产级路线 API。

开发者模式允许：
- 选择测试 fixture
- 设置模拟速度
- 开始/停止模拟
- 必要的最小调试状态

- 多 Agent
- 模型自动路由
- 云 TTS
- 唤醒词
- 摄像头
- Android Auto
- 车机控制
- 音乐联动
- 酒店/餐厅预订
- 支付、日历、消息
- 完整离线知识系统
- 完整 GPS 历史
- 自动 Memory Hub 同步

- 为未来假设预先搭服务器
