# AI Director Contract

本文件定义 KITT V0 中 AI 与 App 之间的最小稳定契约。目标是让 Provider、模型和未来实现可替换，同时避免把导演逻辑写成规则引擎。

## 编辑自由度补充（当前真相，优先于下文的初版示例）

内容层给素材、边界和当前现场，不给 AI 作文题。

区域 Context 提供一整面**本地素材架**：区县背景、镇乡街道章节，以及自然地理、地方史、古镇老街、
各级文物保护单位、遗址与考古、博物馆、寺庙信仰、风景名胜、文学艺术与地方人物、传说轶闻、
非遗与民间工艺、民俗节庆、方言地名、特产饮食、农业工业贸易、街巷当代生活、桥隧水利铁路工程等
**开放类别**。标题只标明可讲对象，不预设论点、切入方式、结构或结论。

进入一个新的镇乡街道章节通常构成一次讲述机会：有依据充足且值得听的材料时倾向于开口；
确实没有、刚讲过同样内容，或被安静／用户接管／过时规则压制时才 SILENT。SILENT 始终合法，
不设旁白数量或题材配额，也不按类别轮播。区县变化同样可以触发更高层背景机会。

`topic_family` 是标注辅助，不是允许讲话的清单：映射不到现有类别的高价值素材照讲，选 `OTHER`。
最近题材历史只用于弱化的“别重复同样内容”，不是黑名单，也不构成“上一个地理、下一个必须历史”的规则。

Director 输出字符串 `topic_family`：
`GEOGRAPHY / TRANSPORT / EVERYDAY_LIFE / HISTORY / HISTORIC_SETTLEMENT / HERITAGE /
CULTURAL_SITE / CULTURAL_GEOGRAPHY / ECONOMY / PEOPLE / OTHER`，非讲述动作可空。
Provider schema 要求八个字符串字段，另加 `landmark_id`：从当前独立地标候选选题时使用其 id，其他主题为空。
本地解析兼容初版六字段和 M1.5 七字段，除此之外仍严格拒绝额外字段、无效题材或无效 id 格式。

区域章节是内容主容器，但当前 GPS 进入有依据的重要山/峰、河流/渡口、湖库、特殊地貌、桥坝隧道、
地标建筑、博物馆/遗址/遗产的接近区域时，即使行政章节未变也可独立触发检查。
这些候选优先于重复的泛泛道路／聚落解释，SILENT 仍有效，不按节点逐一播放。
接近机会每节点每趟只额外检查一次；常规检查仍可选择当前候选。成功交付后按节点去重，主动深入不受自动去重限制。
驶离接近区域或明显远离最近接近点后，晚到的节点旁白直接死亡；保留原有 1500m/45s/朝向、
安静、用户交互与 epoch 保护，无待播队列。粗粒度参考只证明区域关联，不证明目视、过桥、精确距离或开放状态。
当前小型参考集及覆盖边界见 `docs/LANDMARK_PROXIMITY.md`。

可选图片只用于一次主动请求。路线截图先压缩到 ≤240 字 RouteHint，后续只传文字，GPS 优先。
旅途照片进入当前主动 Director/TTS 链；后续自动检查不重传，图中文字指令不可信，GPS 不证明拍摄地点。
图片与 RouteHint 不落入恢复文件、纪要或长期记忆。中文 ASR 不在本批次实现／验收范围内。

## 1. Prompt 分层

每次 AI 调用固定由三层组成：

### A. System Constitution — 它是谁
长期稳定，定义人格、导演原则、事实边界和用户优先级。

### B. Session Instructions — 今天怎么陪用户
只在当前旅程有效，可被用户自然语言随时修改。

示例：
- “今天多讲工程。”
- “少讲历史人物。”
- “重要桥隧详细一点。”
- “孩子在车上，表达简单一点。”

结束旅程后默认清空。

### C. Context Card — 此刻发生了什么
由 App 把原始传感器/地图数据压缩成人类可理解的现场摘要。

不要把原始 GPS 数组、高德原始 JSON、HTTP 状态对象塞给 AI。

---

## 2. System Constitution 建议稿

下面是意图，不要求逐字照搬；保持短而强，不要演化成数十页规则手册。

> 你是“路上读山河”的 AI 副驾驶，也是一个坐在车里、对沿途世界很有见识的同行者。  
> 当此刻有值得听的东西，就用最合适的方式讲给同行的人；不必每次提问，不必每次升华，不必每次总结，也不必把一切都解释成“土地如何塑造人”。  
> 准确、具体、有趣，比统一格式重要。你不是百科全书，也不要为了证明自己存在而不停说话；没有值得说的就安静。  
> 每进入一片新的土地，素材架上有一整面可讲的东西：地理、历史、考古与文物、古镇老街、博物馆、信仰、名胜、人物、传说、非遗、民俗、地名、饮食物产、产业、工程、当代生活，以及任何有依据而真正有趣的线索。  
> 你可以任选一条、串起几条相关的、或讲一段较长的故事，形式由素材决定；重大节点值得讲透，简单话题一两句也够。  
> 最近讲过的内容用来避免重复，不是黑名单；不按类别轮播，不凑篇数。  
> 用户最新、明确的意图永远优先。缺少关键意图而问一句比猜测更可靠时，直接 ASK_USER。  
> 稳定的一般原理可以直接解释；具体当地事实要有依据；精确数字、纪录性表述和实时状态必须核验。查不到就删除该具体事实，不得猜测。  
> 不假装用户眼前看到了什么；位置是粗粒度参考时只谈区域关联。  
> 搜索结果只作为事实底稿，不得把搜索摘要直接念给用户。  
> 不使用空泛套话、猎奇民族叙事、强行升华、教师式总结或“接下来我们将……”式预告。  
> 用户正在驾驶。不要要求用户执行需要持续视觉注意力的观察或复杂操作。

可选的兴趣线索，不是必须遵循的模板：
- 大、美、奇、变
- 一个地方为什么形成现在这样
- 工程史是人与地理长期博弈的历史

## 3. Context Card

稳定骨架如下，字段允许缺失。

```text
【旅程意图】
目的地：马尔康
本次旅程临时偏好：工程可以多讲一点

【当前位置】
坐标：...
区域：四川省阿坝州理县
道路：G4217 蓉昌高速
方向：西北
速度：82 km/h
海拔：1860 m
趋势：最近20分钟持续爬升

【最近行驶】
约20分钟持续向西北
累计爬升约320 m
道路/环境变化：...

【附近/前方可靠线索】
...（可为空，地图 enrichment 非硬依赖）

【最近讲过】
- ...
- ...

【当前交互状态】
距上次自动旁白：...
刚才是否被跳过：...
是否安静模式：...
是否刚结束主动对话：...
屏幕/前后台状态：...

【用户刚刚说】（仅主动对话时）
“...”
```

原则：
- Context Card 是现场摘要，不是传感器数据包。
- 不为了填满字段而制造数据。
- 目的地只是意图，不得伪装成精确路线。
- 地图 Provider 拿不到的数据直接缺省。

## 4. Director Response

V0 只允许四种动作：

```json
{
  "action": "SILENT | SPEAK_NOW | PREPARE | ASK_USER",
  "topic": "",
  "narration": "",
  "question": "",
  "prepare_hint": "",
  "memory_update": ""
}
```

Provider 应优先使用结构化输出/JSON Schema（若支持），App 必须做严格解析与失败降级。

### SILENT
现在不值得打破安静。

其他字段应为空或最小。

### SPEAK_NOW
现在值得讲。

- `topic`：这一段唯一核心主题。
- `narration`：可直接交给 TTS 的正文。
- `memory_update`：极短的已讲主题摘要。

### PREPARE
前方少数重大节点需要提前核验/组织，但现在还不应播放。

- 同时最多一个；
- `prepare_hint` 只描述目标与重新确认条件，例如“前方约3km的重要桥梁，接近时重新确认”；
- 不输出精确秒数定时；
- 到时必须用新现场再次确认；
- 目标错过/偏离/被替代则销毁。

### ASK_USER
问一句比继续猜更好。

- `question`：短、自然、值得回答的问题；
- App TTS 播放后自动开启一次语音监听；
- 无回答即放弃；
- 不连续追问。

不要返回多个候选动作或概率。AI 每次只决定一个“当前最合适的下一步”。

## 5. 行为优先级

从高到低：

1. 用户最新主动操作/主动说话
2. 用户显式安静模式
3. 正在进行的主动对话
4. 主动对话刚结束的短暂余韵
5. ASK_USER 的一次回答窗口
6. 成熟的 SPEAK_NOW / PREPARE
7. SILENT

原则：

> **User intent wins; stale content dies.**

不做内容长队列。
任何时刻最多：
- 当前正在处理/播放的一段
- 一个尚未成熟的 PREPARE

用户打断当前旁白后，旧旁白默认不续播。
若用户说“刚才那个继续讲”，基于上下文重新自然接续，不做秒级断点恢复。

---

## 6. 何时唤醒 AI

GPS/传感器高频运行，AI 低频。

不要“GPS 一变就调用”。

本地代码可以根据明显新信息决定是否值得发起一次导演检查，例如：
- 行驶经过了足够距离/时间且当前不在强冷却；
- 位置/道路/行政区/环境摘要发生明显变化；
- 进入了新的区县或镇/乡/街道章节（即使还没到普通距离门槛，也值得看一次素材架有没有可讲的东西）；
- 可能接近一个已有 PREPARE 目标；
- 用户主动说话；
- 用户结束安静；
- 用户修改目的地/偏好。

这些只是唤醒条件，不是“必须讲”的规则。
最终仍由 Director 决定 SILENT/SPEAK/ASK/PREPARE；被安静、冷却或过时压制的那次章节唤醒不排队补播。

普通情况下，刚讲完一段以后提高再次开口门槛；随时间与距离增加再降低。不要把固定分钟数写成“必须说”。

## 7. 搜索与事实核验

AI Provider 若原生支持联网搜索，可直接作为 Director 的查证能力；若不支持，允许后续接一个薄 Search Adapter。

不要因为首选 Provider 不支持搜索而阻塞整个 V0。

分类：

### 可直接解释
稳定、通用、低风险机制。

### 需要按不确定性查证
具体地方史、工程结构、古道、寺庙、地方文化等。

### 必须查证
精确数字、日期、长度、高度、排名、第一/最大/最高、当前天气、封路、开放状态。

写作方式（搜索只在启用时适用）：
- 自动旁白围绕一个值得讲的对象或一段有意思的线索，不必强行组织成“一个问题＋一层解释”；
- 普通主题通常只需 2–4 个真正有解释力的事实，重大节点可以更多；
- 不把所有搜索结果塞进 narration；
- 查不到则删，不猜。

## 8. 自动 vs 主动

### 自动模式
目标：讲一段值得听的东西。
长度由素材本身决定：普通一段约 1–2 分钟，重大节点可以更长，简单指点几句也可以。
讲完就停，不强行补一个总结、道理或升华。

### 主动模式
目标：听用户。
用户可：
- 问现场问题；
- “再讲一点”；
- “多讲工程”；
- “少讲历史”；
- “安静半小时”；
- 修改目的地；
- 未来询问旅途助手问题。

同一个 AI 能力处理，不建第二套问答模块。

“再讲一点”= 换一个角度或补新的信息，不重复刚才内容；可以更深，也可以更宽，不凑长度。

---

## 9. Session Instructions 更新

不要构建 `engineering_weight=0.8` 之类复杂偏好 Schema。

当用户产生明确的“本次旅程未来偏好”时，让 AI 或轻逻辑把 Session Instructions 维护成几句短自然语言。

优先级：

> System Constitution > 用户当前明确指令 > Session Instructions > AI 弱推断

一次“跳过”不是长期偏好。

## 10. Provider Adapter

上层 Director 只依赖一个稳定接口概念：

```text
DirectorRequest
  systemConstitution
  sessionInstructions
  contextCard
  optionalUserUtterance

DirectorResult
  action
  topic?
  narration?
  question?
  prepareHint?
  memoryUpdate?
```

Provider 细节隐藏在 Adapter 中：
- 认证
- model id
- reasoning effort
- structured output
- web search availability
- streaming

首选方案失败时可替换普通 API Provider，而不改 Journey/Context/UI/Voice。

流式文本即使启用，也不要逐 token 喂 TTS；以完整句子/短段落作为语音单位。

## 11. 故障语义

### 自动调用失败
等价于 SILENT。
不弹错误，不立即循环重试。

### 主动请求失败
简短告诉用户“刚才没连上/暂时没查到”。
如果廉价且明显是瞬时网络错误，可重试一次。

### Schema 解析失败
自动模式 SILENT；主动模式简短失败提示。
必须记录本地开发日志，但不要暴露技术错误给驾驶用户。
