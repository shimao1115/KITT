# V0.5.2/code19 六类讲述兴趣偏好工程验收

本轮任务是 [Issue #34](https://github.com/shimao1115/KITT/issues/34)，交付到 [Draft PR #35](https://github.com/shimao1115/KITT/pull/35)。只做本地工程：不操作手机、不安装、不合并、不上传或发布 APK、不审批任何故事。

## 做了什么

设置页新增单一「讲述兴趣」区块：`NATURE / ENGINEERING / CULTURE / LOCAL_LIFE / HISTORY / TRAVEL` 六类，各提供「多讲／正常／少讲」三档，初始**全部正常、彼此均衡**。中文游客标签为自然地理生态、交通与工程、人文文化社会、物产产业生活、历史与人物、旅行现场与常识。旧 `TopicFamily` 与对象 `family` 不参与推断，也不映射成这六类。

偏好写入**独立的 `story_interests` 偏好文件**，有自己的保存按钮：不改用原「保存」路径，因此不会重新加密账号、不触碰 `provider / model / effort / tts_voice / speech_rate / chatgpt / credential / research_*` 任一键，也不启动 Journey、不改定位、不重置语音生命周期。code18 旧配置升级后没有这些新键，读取即全部正常；非法值、空值、类型错的值一律回退正常且不崩溃。返回或离开页面不落盘，只有明确点「保存讲述兴趣」才写。

排序是**门禁之后的柔性优先**：`StoryPacks.select` 仍先过区域匹配、内容审批、Fact/Visitor Gate、版权、Claim 修订与来源证据、可信定位、本趟已播、节奏与延伸条件，之后才用 `StoryRanking` 按类别调相对次序。稳定排序保证全正常时结果与旧行为逐字一致；少讲不禁讲，多讲不能让不合格候选入场，也不能造出第二个主篇（现行 `stories.count(main) <= 1` 数据门禁保留）。偏好只作用于**自动讲述**；用户明确点名、原文重播、探索阅读与手动点播不受偏好排位。

## 现在还不能声称什么

标准包与本版 runtimecheck 的**正式完整故事仍是 0**。杨慎主篇与延伸仍 `candidate / fact_gate=passed / visitor_gate=pending`，正文、Claim、审批、manifest 和标准资产逐字节未改，`--require-playable` 仍如实 BLOCKED。因此「真实多类成品故事在手机上被偏好改变了播报次序」这一条**尚未验证，记为 PENDING**；本轮用纯内存 `TEST_ONLY` 多类别夹具证明排序逻辑本身可用，不注入 APK、不提升审批。设置页也如实显示当前没有已通过门禁的完整故事。

离线优先／即时优先两档来源模式**本版 DEFERRED**，未实现、未测试，也没有只做 UI 的假开关。

## 用户后续最短人工验收（本文不构成安装许可）

1. 先审 Draft PR 代码与工程证据，核对本地候选 APK 的包名、versionCode 19、大小与 SHA256；是否升级手机由你另行明确授权。
2. 升级后先别动其他设置：打开设置页，确认六类都在、初值都是「正常」，且账号行、Provider、模型、思考强度、音色和语速与升级前一致。
3. 只把「历史与人物」改成多讲、「交通与工程」改成少讲，点「保存讲述兴趣」，退出应用再回来，确认两项仍在、其余四类仍正常。
4. 回到驾驶页正常跑一段新都区旅程，观察讲述内容与不报错即可；**当前没有正式完整故事，所以不应看到「偏好让我多听了某类故事」的结论**。旧的 20 份纪要与设置也应保持原样。
