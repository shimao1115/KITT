## 1. 一张图理解知识工厂

**合法来源 / 人工研究 → AI 发现及事实抽取 → 独立核验的 Fact Pack → AI 写作、事实复核及游客试听的 Narrative Pack → GitHub Releases → KITT 在真实位置选择故事 → 手机本地中文 TTS 播放。**

| 资产 | 具体内容 | 存储原则 |
| --- | --- | --- |
| 研究来源与审稿资料 | 书目、真实访问记录、精确原文位置、支持/反证、许可、冲突和审查报告 | 合法源登记放 Git；版权受限原文、PDF、扫描、视频仅在有明确权限的办公室或家庭电脑工作区中按许可处理，不公开镜像；工作区不可成为用户侧分发服务器 |
| **事实包 Fact Pack** | `Area/Entity/Claim/Source`，原子事实、来源关联、年代/位置/别名、稳定性 | UTF-8 JSON/JSONL 源码存 Git；发布时可以压缩为供手机读取的结构化文字数据 |
| **讲述包 Narrative Pack** | 审核完成的主故事、延伸故事、关联故事、逐篇 `supported_claim_refs` 与语言/位置适用性 | 纯 UTF-8 文字/JSON/Markdown 存 Git；发布可以压缩，但只携带文字和元数据 |
| 正式可安装成品 | 独立 Fact 与 Narrative 数据包、清单、哈希、兼容性与签名元数据 | GitHub Releases；不在 Git 主历史囤二进制成品，不以 Actions 临时 artifact 代替长期发布 |

**不保存或发布音频知识包**：不上传 MP3/WAV/预制配音/录音，不把云端或本地音色写死进知识包。手机 TTS 引擎或未来更好的本地语音模型与知识包分别安装、升级和选择。文本可包含通用分段、停顿、读音提示，避免特定供应商专有控制语法。

**两个正交维度**：全国基础包/省级通识包/市州详细包是**地域层级**；Fact/Narrative 是**内容类型**。Overview 和 Topic 是**内容的发现/检索视图**，不是第三种独立的物理包。省级通识不应成为城市包的强制下载前置；每个故事只声明实际使用的 Claim/区域依赖，缺少必须的上层事实时自动获取可共享依赖或不激活那篇故事，不允许悬空引用。

**产品入口**：普通游客应能选择“下载某地区完整离线内容”，系统自动准备适配的事实与讲述包；可独立更新，用户不需知道文件结构、不需 API Key。首次下载可能联网，但开车途中不依赖互联网或 GitHub。

## 2. 生产设备与发布中心：办公室/家庭电脑 → GitHub

**NAS 已正式退出本产品的知识生产、存储与分发架构，不保留备份 NAS 路线。**

- **仅在办公室 Windows 电脑和家庭 Windows 电脑生产**：在两台电脑上使用获授权 AI 完成资料检索、抽取、核验、故事写作、试听、构建。不架 NAS/自托管知识中心、持续在线的爬虫服务器或同步平台。
- **GitHub 是唯一正式协作和分发中心**：App 源码及规范在 `shimao1115/KITT`；计划中的 `shimao1115/KITT-PACKS` Git 仓库接收可公开的文字事实、文字讲述、来源记录、审校文件和构建脚本；GitHub Releases 发布通过验证的压缩知识包及版本清单。当前第二仓库/发布器尚未实现。
- **两台电脑是工作站，不是分发服务器**：从最新 Git commit/Issue/PR 接班，本地只留合法施工工作区；向 GitHub 合并有据可审的结果。版权/保密资料如无权公开，则按许可只在授权工作区处理，不上传 GitHub，也不得通过外部大模型接口违规上传。
- **使用时手机独立**：有下载好的内容、可信位置及本地 TTS，断网也能讲述，不要求联到电脑或 GitHub；GitHub 不承担手机沿途实时查询 API。
- **构建可复现**：不依赖 H: 盘或特定主机环境，办公室/家用电脑读取已提交源与版本化工具即可重建一致的知识包。

## 3. 多模型标准工作流程：先核实，再讲故事

| 阶段/可替换角色 | 实际工作 | 必须留下的交付物 |
| --- | --- | --- |
| **Scout** | 按六类并列主题和 L0—L6 来源目录寻找现象、对象和文献 | `inventory`、来源候选、真实链接/书目信息、哪些原文已读/未读 |
| **Extractor** | 逐条阅读合法来源、别名归一、抽原子 Claim | `entities/claims/sources`，精确 `source_id+locator`、适用时间/地域 |
| **Independent Verifier** | 重新打开独立证据，检查事实与出处是否匹配、存在争议/转引同源或版权风险 | `verified|contested|lead|rejected`、支持/反证、复核时间与问题 |
| **Story Writer** | 只依据已核实 Claim 写游客主故事、延伸及关联篇 | 独立、完整可直接朗读的中文文本、`narrative_id`、`supported_claim_refs` |
| **Story Reviewer** | 逐句回链 Claim，对普通游客零背景理解、兴趣和语音节奏审稿 | 事实 Gate + 游客 Gate、试听结果、修订意见；没有真人审过不能自称真人 PASS |
| **Builder/Publisher** | 程序校验、依赖/版权/版本、可复现构建、发布与回滚 | 构建报告、两个 manifest、固定 commit/tag、校验摘要、受控 Release 链接 |

**人和模型的职责**：可让同一 AI 完成低风险的发现+抽取+写作以节省成本，但不能靠“换个模型复述相同来源”冒充独立证据。论文、官方原公告、地方观察各自核验其实际支持的说法。高风险与争议要人审，成品故事须抽听/必要时真人终审。AI 不是事实来源，更不是可自行填写“已阅读”“已试听”的证明人。

**首次听到的主故事**：必须先交代地区/人物等必要背景，再讲为什么有趣、事件/机制以及收束，避免首次杨慎只讲籍贯状元官职；不依赖用户点击“再讲一点”才完整。延伸故事跟着兴趣走，**不是一次自动串播整部百科**。山川、地质、工程、生活、风物与历史同等可写，避免历史优先配额。

## 4. 数据契约、事实修订和讲述失效

- 统一稳定 ID：`area_id / entity_id / source_id / claim_id / narrative_id`。同名别名归一；跨区域的山河/人物/工程可引用同一对象。地点关联和“用户此刻可见”严格区分。
- **事实**至少记录：正文（一条可验证论断）、主体、地域/时间、`archival|stable|refreshable|realtime` 类别、`source_id+locator+relation` 及验证状态、可追溯修订。正式静态包不得把实时票价/路况/气象冒充最新。
- **讲述**至少记录：`narrative_id`、`story_type=main|followup|related`、标题/中文正文、对象及地区、`supported_claim_refs`（Claim ID + 接受的修订/内容指纹）、`review_status`、大致时长、适用空间及条件；引证继承事实而不是自己捏一套网址。必要时记录过渡句不增加新事实。
- **版本依赖粒度**：两包各有 `pack_id/content_version/schema_version`，且讲述逐篇指向**它真正使用的 Claims**。某 Claim 被改错、撤销、证据降级或许可变化，**只将依赖它的讲述标记待审/不可播**；更新其他人或其他地区无关 Claim 不能让全部故事失效。更换格式须声明兼容/迁移，不直接默改已发布版。
- **只承认审过的稿子**：`draft/lead/rejected` 不能发布为正式故事；争议内容只有明确归属观点、经复核仍值得讲时才有谨慎表述。缺来源、时间或地理可信度就宁缺毋滥。
- **实际文件格式**：生产侧推荐 Git 可比较的 UTF-8 JSON/JSONL/Markdown + Schema；手机可使用 JSON/压缩文本容器/SQLite，**必须在后续获授权工程对接 #20 的实际 runtime 后确定**，不能凭这份规范声称已实施。

示意（**不是可发布的真实杨慎事实、不是 Android 最终 Schema**）：

```json
{
  "narrative_id": "narrative_example_001",
  "story_type": "main",
  "entity_ids": ["entity_example"],
  "area_ids": ["example_area"],
  "text": "【示例占位；没有事实核验，不得进入正式版】",
  "supported_claim_refs": [
    {"claim_id": "claim_example", "accepted_revision": "example_only"}
  ],
  "review_status": "draft"
}
```

## 5. GitHub 仓库布局（计划，不假装已经建好）

Git 只保存**文字事实/讲述源、合法可公开的地理结构化索引、出处元数据、审核结果和构建脚本**；大件受限原文、录音、扫描、地图瓦片不能因为有 GitHub 就顺手公开。

## 6. GitHub 多 AI 协作：Issue → 分支 → PR → 审核 → Release

1. **Issue 认领一个地区或对象/阶段**：需 `task_id`、`area_id`、已研究对象、`paths_owned`、来源范围和权限、输入 commit、事实/故事应交付清单、验证门槛、未完成项目。一个 AI 写一个对象时其他 AI 可只审稿，避免同时修改同一文件。
2. **独立分支提交 PR**：持久交接只有 Git 文件、来源坐标/出处、审稿结论和 blocker，不依赖上一工具聊天和私有推理。禁止多工具直接并发推 `main`。
3. **事实与故事独立审稿**：先让 Fact PR 经过出处复核，再用认可的事实写 Narrative PR；即使同一 PR 提交，必须清楚区分证据、文学文字和谁验收。不要为优美叙述篡改事实。
4. **自动测试**：Schema、ID/别名/引用、真实 URL/locator 的元数据存在性、依赖的 Claim 修订、版权状态、跨地区引用、动态事实禁入、是否包含音频/密钥、包完整性、字数/首次故事完整性提示。程序只能校验结构/部分可自动核对的证据，**不能自称已人工试听或已亲自核查历史真伪**。
5. **审查合并**：`TODO → WORKING → REVIEW → ACCEPTED`；失败 `BLOCKED/NEEDS_FIX`；`RELEASED` 只属于实际出版的包版本。Claim 审核状态与工单状态彼此独立。合并到 main ≠ 已上架。
6. **错误溯源**：修改 Claim 时自动列出影响的 `supported_claim_refs` 和对应讲述，必要时只封禁/回炉这些篇章，保持其它合法故事可用。

不同 AI 可通过 GitHub Connector/MCP 接入；没有接入的工具只输出符合 Schema 的文本，由获授权工具提交，不谎称自己创建了 Issue/PR。

## 7. 打包/发行/安装（按地区双包，用户一次选择）

> **客户端的状态、更新时机与容错唯一依据**：[KITT 离线知识包管理与更新标准 V1.0](KITT_OFFLINE_PACK_MANAGEMENT.md)。本节仅规定生产与打包侧如何提供足够 manifest、权利和验收材料；不得另外发明不同的自动过期/删除/更新策略。

- **产物**：每个范围可独立发布两个文字数据资产 `fact_pack` 和 `narrative_pack`；必要时“某城市完整内容”一个按钮自动下载/激活匹配的双包及国家基础数据。城市知识包通常不强制依赖全省包，但有实际跨包 Claim 依赖时必须精确解决。
- **manifest**：`pack_id`、`kind=fact|narrative`、`region_scope`、`schema_version`、`content_version`、`source_commit`、`app_compatibility`、`dependencies`、`required_claim_refs`（讲述包逐篇依赖可在其索引中）、`source/rights_summary`、`record_counts`、大小、完整性摘要。整包摘要放外部 Catalog 或 Release 避免自哈希循环。
- **构建确定性**：从固定 commit 和工具版本/配置重建同样的逻辑内容和哈希；规范化排序及时间戳，构建/验收日志不得冒充正式素材。
- **上传正式版**：锁定 tag 后经独立 QA/必要人工核查上传 GitHub Releases 的**文字压缩数据和 manifest**，更新 catalog；新修订发**新版本**，不悄悄替换相同发布版本。GitHub Actions 的临时 artifacts 不作为长期成品库。
- **安全完整性**：SHA256 发现损坏，但不能证明发行者；对公众自动下载安装前须有可信发布者校验（独立于 APK 私钥的签名/公钥或其他等效机制）。客户端暂存下载→哈希/来源/格式/依赖检查→原子激活→失败保留兼容旧版。
- **发布给普通用户看的真实元数据**：每个版本的 manifest 与 catalog 应提供能实际计算的地区覆盖（已验证对象数/完整主故事数/覆盖镇街）、版本/更新时间、兼容关系、所需存储、变更类型与人话更新摘要；**城市已下载不等于城市所有镇街都可讲**。日后让手机检测更新时不得把 GitHub Releases 当实时联网内容数据库。
- **正式发行不强迫旧包过期**：历史和稳定知识继续允许使用；涉及证据撤回/许可或重大错事实时，明确标记受影响 Claim/篇章；无关故事与旧包无需整体被停用。离线设备无法同步最新撤回信息时不得伪称已知最新撤回状态。
- **无 API 基础门禁**：无网络且未配置 AI 时，若事先有合格的事实和讲述包、可信位置与本地中文 TTS，必须能够听完整主故事、延伸故事、重播/静音/打断。有网无 AI 也一样能听；已配置 AI 断网自动退回；有网有 AI 才开启自由问答、图片理解、搜索等增强。
- **能力不装懂**：没装包、没可靠位置、没离线 TTS、故事受事实修订影响或仅有动态资料时，应说明不可用并允许安全降级，不能拿碎片介绍冒充主故事、把历史知识当实况。

## 8. 客户端来源策略与包生产的关系（离线优先/即时优先）

**模式改变运行时的讲述来源，不改变知识工厂的事实和讲述包生产规格，也不让 GitHub 变成模型 API。**

- **离线优先（默认）**：有可用成品 Narrative 的正常播报不调在线模型；用户提出天气/路况/今日变化或知识包外问题时，网络与用户模型配置齐备才临时走在线生成/真实来源查询，答完不改变默认。
- **即时优先（用户显式设置）**：常规自动介绍由在线 AI 即时组织，但**先从本地 Fact 及必要的已审核 Narrative 检索相关可信素材**，只把必要的 Claim/片段放进模型上下文；事实不足或涉及新鲜消息时才通过实际可用的在线搜索补充。**旧版“即时优先默认跳过两个本地知识包”方案废止**。依然执行可信位置、已播记忆、TTS 安全和来源门禁。
- **未配置 API、网络断开或在线请求失败**：提示并回退本地已审稿讲述，不清除或卸载离线包，不把回退播报冒充“最新在线生成”。
- **必须测试的分支**：离线优先常规不调用模型、用户单次提问先本地检索且需要时临时联网、即时优先 AI 生成但使用相关本地事实、断网/无模型时明确回退，以及模型调用数量/时延/费用展示；均属未来客户端实施。
- **开关位置与 UI**：建议设置页双档选择，默认离线优先，驾驶中快捷入口视可用性另定；本次只定行为，不擅自修改 #20 APK。

## 8A. 探索地点（主动看/点选/可选播放）的制包门禁

- 用户已**定名“探索地点”**。其可独立于实时 GPS/Journey 查询当前位置或用户指定的其他地区（如新都区、马尔康市）；**本地包有资料先列本地真实对象**，没有已安装包且实际具备网络/AI 才调用在线临时检索。不把在线临时结果直接变成官方离线事实和成品故事。
- **Fact 为目录和检索索引，Narrative 为全文阅读与可选 TTS 的内容**。需提供可展示的主题标题/类型/简短说明、区域/对象 ID、完整主故事正文和审核状态、followup 关联、Claim 引证；**没有成品讲述时标明“仅基础事实”**，不虚构稿子或把临时回答伪装成审核故事。
- 用户点击主题应先**看到完整讲述稿文字**；正文下面的**播放**按钮仅在主动点击时用手机当前本地 TTS **朗读同篇文字**，不需要云 API，不生成预制音频或随包发 MP3。文字不因播放而消失；若无可用 TTS 仍可阅读。
- 讲述来源的两档模式不控制探索页面是否查本地：即使用户选择“即时优先”，**探索地点仍优先找本地地区与讲述包**；用户主动要求在线搜索或本地缺资料时才转在线。AI 自由问答同样先按地区/对象/关键词检索本地可信 Fact，必要时再研究。
- 后续真机验收包括：离线无 API 读杨慎全文并点击播放、查看其他话题，异地搜索已装包、异地缺包和在线临时结果来源、没有 TTS 的文字可读性与驾驶中只允许安全交互。**这是开发验收建议，不代表 code14 已有界面**。

## 9. 小样本验证与当前施工 STOP

**首次最小黄金路径**（用户后续单独授权后实施）：利用已经有来源的新都事实作候选底稿；补齐杨慎等人的关键经历、代表作品和背景证据；编写至少一篇**有背景、有趣味、有结尾**的主故事及合理延伸篇；另一模型回证据逐句核验，真人试听；手机真实无网络、无大模型 API，以既有本地 TTS 完整播放；验证事实修订只使其依赖的讲述失效。

再让另一台电脑或另一个 AI 只读 Git 源与任务卡，在不读取上一个模型聊天记录的条件下重建两个内容包，并验证 Schema/引用/哈希与手机号端读取。优先测**故事质量和证据闭环**，不按每天新建多少条、模型调用次数评估产能。通过后才扩到成都其他区、四川、全国。

**本轮依然只有“整理并统一规范”的授权**：不得趁机建真实仓库、改 Android 代码、开自动爬虫、提交媒体、制作音频包、发布新的 APK 或修改 V0.4.0/#20 的工程结论。
