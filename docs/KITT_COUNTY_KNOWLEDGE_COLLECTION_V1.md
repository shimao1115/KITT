## 1. 五种不同粒度，不可混为一谈

| 粒度 | 对应实体 | 用途 | 是否独立下载 |
| --- | --- | --- | --- |
| 全国基础 / 省级通识 | 全国、跨省/省域共享事实与必要索引 | 可复用基础、跨区域山河/文化/工程 | 全国可有基础包；省级视需要 |
| **县级行政单元** | 市辖区、县、县级市、自治县、旗等经核实的县级单元 | **最小地区采集工单、独立可审计版本与未来的最小详细发布包** | **目标：是，Fact + Narrative 成对提供** |
| **乡镇街道** | 县下每个现行乡、镇、街道及具备合法身份的同级辖区 | **必须逐一完成基础普查**，组织沿途章节与待调查主题 | **否**；是县包内索引与内容覆盖单位 |
| 对象 / 专题 | 人物、遗址、寺庙、村落、桥梁、隧道、河流、产业、工艺、山体、地质现象等 | 事实/故事的主要研究和选择对象 | 否；可以跨区引用 |
| **原子 Claim / 单篇 Narrative** | 单条可验证事实 / 一篇主故事、延伸、关联篇 | 最小事实修订与依赖失效 / 最小阅读与播放单元 | 以其所在县包或共享包提供 |

**市州入口是聚合，而不是重复存一套内容。** 例如用户选择“德阳市”，客户端组合广汉、旌阳、绵竹等已实际发布的县包；“已安装德阳市部分区县”必须如实显示，不能说全市覆盖。县级可单独安装和更新，跨市路线自由组合。其他未做的县不能因同属德阳而标记已完成。

**县级行政身份和代码以最新权威来源及有效日期为准。** 中国存在县级市、自治县、旗等不同名称；本协议中的“区县”是统一的县级分包概念，不把所有单位硬写成“区”。行政撤并/更名保留历史 ID 映射、有效时间和迁移关系，不直接覆盖老资料而丢出处。

## 3. “全面采集”的可验收定义

全面是**范围与调查过程完整**，而非宣称录尽一切知识或每个乡镇六类故事数相等。

每一个县级工单至少交付：

1. **Area 底账**：官方行政名称/代码、上级归属、核验时点、所有现行镇/乡/街道的名录（如有特殊同级单元如实处理），常见别名、撤并关系、可合法使用的基础空间数据及其来源/许可。
2. **镇街逐一普查**：名录中**每一镇街**均建立调查记录；调查六类主题的潜在线索——自然地理与生态、交通工程、人文文化与社会、产业物产与生活、历史人物与事件、旅行常识。无可核实线索可标“已扫描未发现可靠资料”，不得空白冒充完成，也不得强凑篇章。
3. **实体清单（inventory）**：县域背景及镇街层的高价值实体均记录稳定 ID、别名、实体类型、关联区域、主类别/可选副类别、为什么值得乘客知道、真实来源线索、空间精度和后续处理优先级。允许跨镇街/跨县实体仅存一次、用关联索引引用。
4. **Fact Pack**：把可证实的稳定叙述拆为简洁 Claim，保留 source_id + 精确 locator/引用关系、证据状态、修订指纹、时间/地点适用、权利与共享对象关联。资料只有标题/搜索摘要，标线索，**不得自动标已核实**。
5. **Narrative Pack**：每县有适宜普通人理解的区域概览候选；选择有价值的对象写自然、独立成篇的主故事，真正有新事实再写延伸/跨区相关篇。不要求每镇一个故事，也不要求每实体都有 Narrative。只有 Fact 的内容在“探索地点”必须显示“基础事实”。
6. **缺口报告**：明确没有来源、地理边界不可得、只能区县触发、尚无故事、资料冲突及版权不可公开的项目。区县标记“基础普查完成”不等于“所有故事完备”或“真机可播全域”。

### 覆盖统计要分层

- `镇街普查覆盖率 = 已有**有效普查结果**的现行镇街数 / 名录中现行镇街总数。首次完整普查交付时目标 100%；“无可靠资料”也是一种**明确调查结果**，而非可播故事。
- `主题扫描覆盖率 = 已执行六类扫描的镇街/类别组合数 / 现行镇街数 × 6。允许“该类别未找到有根据的对象”；不允许未查即记完成。
- `有效 Fact 覆盖：实际有合格 Claim 的镇街/对象数，**仅以审核通过记录计算**，不要从 inventory 猜算。
- `讲述覆盖：真实已批准 main/followup 数及实际关联的镇街/对象数；不得用草稿、拼接短介绍或地级市已下载状态抬高。
- `空间触发覆盖：已持有**可用、合规、经过核验**的区域多边形/对象位置且精度足够的单元数；不同于“镇街目录覆盖”。

记录各自分子、分母、数据日期和未满足项。**没有固定的每县主题篇数上限/下限、来源篇数硬指标或按学术论文数量强行考核。**

## 4. 六类发现清单（每镇逐一调查；不可强凑）

| 主类别 | 重点线索与对象举例 | 不能做的事 |
| --- | --- | --- |
| NATURE 自然地理生态 | 山脉、河流、地质、气候规律、山前与平原地貌、植被与保护 | 不能把长期规律当今天实时天气 |
| ENGINEERING 道路交通工程 | 公铁路线、桥隧、古道、运河水利、工业/基础设施技术 | 不能把历史建设信息当实时通行状态 |
| CULTURE 人文文化社会 | 古镇、文保建筑、博物馆、地方艺术、非遗、风俗、建筑与聚落 | 不直接转载受版权保护的文章/图片 |
| LOCAL_LIFE 物产产业生活 | 农林特产、工厂产业、饮食、手工艺、市场与贸易 | 不把商家宣传或旅游软文直接当事实 |
| HISTORY 历史人物事件 | 地方人物、历史事件、遗址考古、地方志记载、地名变迁 | 不把争议、传说直接讲成确定史实 |
| TRAVEL 旅行现场与常识 | 季节性可观察现象、观景背景、地方旅行知识 | 不离线保证票价、营业、路况、实时可达 |

类别指**讲述角度**，不等于对象类型，也不等于是否需要独立的物理包。一个实体可关联多个类别，但每篇 Narrative 恰好有一主类。

## 5. 资料发现、核验与文字交付的最短流水线

1. **确认行政基准**：取权威行政区划/县级政府机构资料和时间戳，核完整镇街名录；发现资料版本冲突要标注，暂不据无来源地图划镇。
2. **镇街批量“广扫描”**：优先政府公开资料、文博/自然资源/交通权威机构、经授权地方志与专业资料；再以二手材料寻找线索，形成 Source Registry 和 inventory。先收哪些值得讲，后决定哪些值得写主篇。
3. **实体去重与地理关系**：同一山脉/河流/工程/人物跨县只留一个稳定 entity_id；县域专题只是关联，不复制相冲突的来源事实。每个对象要区分“与本县有关”和“车当前附近可见”。
4. **提炼事实**：一 Claim 一可核实断言，标时间性质 archival/stable/refreshable/realtime（实时不当作永久离线知识）；记录 source_id、原文位置、证据支持/反证与权利。关键或有争议说法优先交叉核；一般低风险内容可以依充分的可靠原始来源快速核实，不按历史综述方式机械追逐每篇论文。
5. **制作讲述**：至少可以独立说明来龙去脉、能让普通乘客听懂、有真实新信息的篇章才入 Narrative；上下文友好、车听自然、不过分长，文字与事实精准链接。
6. **审稿/可播门禁**：自动结构检查 + 真实来源支持核查 + 人认可的范围 + 阅读/必要时 TTS 试听；不伪造已访问/已试听。审稿证据按正文 SHA 与接受的 Claim 修订绑定。
7. **定版/分发**：每县两层包分别有版本、manifest、摘要、兼容性与版权状态。正式发版时对可信发布者、完整性、依赖和失败回滚做工程验证。只发布合法可公开文字和地理索引，不制作录音包、不镜像受限扫描件。

**可并行工作**：新都现有试点先完成一次旧数据映射和产线验证；其余五县可在此基础上并行调查，每县各自 Issue/独立目录/PR。全局 sources 和 entity IDs 通过合并时统一去重，防止几个 Agent 同时写同一路径。各县的“事实普查”和“完成全部 Narratives”可分别交付和显示不同状态，不让一个难以找资料的景点卡住整县扫描进度。

## 6. 最小文件组织（生产端示意，不代表现有 Android Schema）

沿用现有 [知识工厂 V2.4](KITT_KNOWLEDGE_FACTORY.md) 的县级目录示例，未来计划中的 KITT-PACKS 仓库可以这样组织：

```
registry/
  areas.jsonl                   # 行政身份/有效时段/别名关系
  sources.jsonl                 # 全局复用来源；记录真实访问与许可
regions/cn/<省代码>/<地级代码>/<县级代码>/
  inventory.json                # 县及镇街的调查进度、类别覆盖、缺口
  townships.jsonl               # 经核验的每个现行镇乡街道（采集目录）
  facts/
    entities.jsonl              # 对象；跨县共享者引用统一 entity_id
    claims.jsonl                # 可追溯原子事实、版本
    review.json                 # 事实审查结果
  narratives/
    <稳定 narrative-id>.json    # 经审校的完整中文讲述稿
    review.json                 # 内容审核、听感与状态
  coverage.json                 # 真实覆盖统计分子分母/日期/缺口
catalog/                        # 全国/省/市的聚合索引，不复制县包正文
```

上面是**可复用的文件布局建议**；先用已存在的字段/工具映射，不引入第三物理知识包或无必要的新 Schema。具体数据字段至少需要：

| 记录 | 最少能回读的数据 |
| --- | --- |
| County/Area | 稳定 ID、层级/父级、名称/别名、行政有效日期、source、空间信息是否真实存在 |
| Township Survey | 镇街 ID、parent_county_id、六类 `扫描状态、发现对象 IDs、调查日期、来源/缺口 |
| Entity | entity_id、实体类型/别名、area 关联、类别线索、时空属性、locator 可信度 |
| Claim | claim_id + revision、说法、证据 source_id + locator、状态、适用时地、权利 |
| Narrative | narrative_id、main/followup/related、正文/哈希、对象/区域、Claim 精确依赖、审核/可播状态 |
| Manifest / Coverage | 包版本/Schema/App 兼容、摘要、准确数量、镇街调查结果、版权状态、缺口 |

全国目录和市州目录**只做索引/聚合**，不能复制六县正文成彼此独立的六份同名对象；一个城市的“全部下载”=组合本市实际存在、兼容、已批准县包及必要共享依赖。

## 7. 空间定位、许可和全国推广的硬边界

- **镇街名录有据，不等于 GPS 已能准确识别镇街。** 必须区分行政归属证据、合法镇街多边形/精确位置证据、实时可信 GPS、目标对象可视/可抵达范围。
- 没有可信镇街边界时可以用真实县界做县级广播，并允许人工探索镇街目录；不能把县内任意 GPS 坐标赋给某镇，也不能把“属于这个县”当“看得见某遗址”。
- 多边形要检查数据来源、版本年代、许可证、坐标系/中国相关测绘与分发限制；不能因它是 JSON/GeoJSON 就自动合法可公开。
- 允许跨区实体、非连续行政辖区、历史改名及同名地名；ID/别名要有唯一性和时间范围，不能只用地名字符串做关键索引。
- 从地方志、景区/政府官网、百科索引发现资料时只保留合法摘要、来源与必要引用信息；不能公开上传版权受限全文/照片，非原创录音和音色不入知识包。
- 县包独立生产和升级必须验证具体 Claim 依赖；一处事实修订只影响用到它的故事，不因县/市版本更新停用无关故事。

## 8. 首批六县分阶段交付、并行安排与验收

### 阶段 A：主程序功能闭环（当前优先）

先完成“听沿途 / 探索地点 / 问 AI / 离线知识管理 / 六类偏好与模式 / 基础 UI”可实际验证的功能。可以用已验证的新都样本和**明确标测试的假数据**检验县包下载/组合/回退；无需等六个县的真实全面采集完成才能验收 App 框架。

### 阶段 B：县级模板迁移与普查

将新都已有 6 对象/22 事实及 V0.5.0 杨慎两篇按实际审查状态映射至县级目录，验证不同版本/跨县引用/来源台账。确认可复现后，六县分别建立工单与行政底账，逐镇扫描六类，形成对象发现目录及真实缺口；**全部现行镇街已扫描并非全部镇街都有故事**。

### 阶段 C：高价值主题成品化与独立发行

以综合价值而非固定配额选题制作 Fact 与 Narrative；各县分别审核、打包、签名/校验、发布/更新，跨县实体去重。县包数量可按真实调查成果逐步增长，不要求六县同步“故事写完”才允许合格县包上线。

### 工程与体验验收清单

- [ ] 六个县级工单的行政名录来源、日期、县级身份与镇街全集均清晰可回读
- [ ] 每县所有现行镇街已有六类扫描记录和发现/未发现/受限原因；coverage 分子分母来自真实记录
- [ ] 所有入包 Claim 与 Narrative 有稳定 ID、真实来源/许可、修订和可追溯精确依赖；无悬空引用
- [ ] 草稿、访问失败或未批准材料没有被冒充成已核验可播故事
- [ ] 新都已有资产不丢失；共享对象/跨县关系不复制成互相冲突版本
- [ ] 各县可独立组包/更新/失败回退；市级聚合只列实际存在的县包，包安装状态真实
- [ ] “探索地点”可浏览县→镇街→主题、完整阅读和手动 TTS；无包/仅 Fact/定位未知时提示准确
- [ ] 可信位置与离线 TTS 能从已安装数据讲述；无镇界不会触发假镇街到达，跨县移动不反复播相同对象
- [ ] 演练至少一次**非相邻区县**的独立安装、检索与更新，以证明架构不是绑定成都—绵阳这条路线
- [ ] 各县提交实际文件大小、版本、覆盖情况、可复现构建结果、未完成问题及必要真人验收结果
