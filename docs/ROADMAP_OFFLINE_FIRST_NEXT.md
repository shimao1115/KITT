## 决策理由与产品底线

- **运行时的主要价值从“每次都能调用在线 AI”转为“优质离线知识随时可看、可听”**。云端 ChatGPT/兼容模型/搜索属于可选增强，而非基础讲述、探索地点、打开已装知识包的必要依赖。在线与离线优先仍是用户偏好，但无网/未配置云 AI 的核心体验也必须完整。
- 用户目前偶发看到“上次请求失败，等待下次触发”，怀疑 ChatGPT 账号/翻墙网络链路。**未经诊断不能断言是账号、代理还是 provider API 的根因**。这类非阻塞在线故障先留记录，**不集中投入时间重新调登录、模型列表、VPN/路由和稳定性热修**。
- **与“不修在线连接”不同，离线链路必须有最小失败隔离**：云调用超时或不可达时及时结束等待；离线优先可用则继续本地选择/播放，不反复重试/重复报错/占用 TTS 或 Director；必要时以简短状态说明，绝不把 AI 失败显示成离线包失效。没有可信 GPS 不假设具体所在位置；若用户主动“探索地点”，可以按地区文字搜索而不依赖 GPS。
- **明确功能边界**：没有云模型时无法保证对任何随意问题作开放式智能回答，离线只能从已下载可靠 Fact/Narrative 做故事浏览、相关事实查询与支持范围内的有限指令/问答；今日天气、路况、营业等仍需要真实及时数据。
- **不得退步的保护**：不卸载 App、不清除账号/设置/旧旅程数据；持续沿用原签名、原 runtimecheck 包名与合法递增版本号；测试区分模拟工程 PASS 与真机、真实物理位置、断网和真人试听的证据。

## 新增正式主路径原则：开口不等待大模型

**2026-10-14 用户进一步确认：“多数时候彻底脱离在线大模型运行；只有临时向模型提问才真正使用它。”** 这应落实为**离线本地原生主路径**，而不是“先尝试云 AI，失败后才找本地备胎”。

1. **正常自动讲述（默认离线优先）**：可信物理位置/已明确地点 → 已安装且兼容的 Fact/Narrative → 本地选题 Director（地理关联、六类偏好、故事可用性、已播、冷却、中断/静音）→ 手机本地中文 TTS。**不得先发任何云端 Director/Research/ChatGPT 请求、等待在线模型回应、要求先登录账号、在线模型列表成功或代理 VPN 可用，才判断是否开口**。没有值得讲且有证据的故事就安静，不为填时长向 AI 要内容。
2. **主动打开探索地点**：从用户指定地区或真实当前位置查安装包 → 本地列表 → 完整已审稿文字 → 用户点“播放”才本地 TTS。**无需账号、外网、在线模型或 GPS（异地主动搜索）**。
3. **独立按需在线分支**：明确开放式/临时问题、今天路况/天气/开放等需要可靠新鲜资料时，用户发起才调用实际可用在线 AI/搜索；若用户**显式切到“即时优先”**，允许正常自动播报改走当次在线 AI 组织，但仍优先参考相关本地可信事实，并说明成本/网络条件。**绝不因为账号曾登录就自动在离线优先下恢复每次云研究**。
4. **彻底故障隔离**：在线请求超时、无网络、代理失效、ChatGPT 模型列表不可用等，仅影响对应在线能力。不得全局设置“上次请求失败，等待下次触发”来挡住本地选题/TTS，不允许无界自动重试、反复弹窗、占用播放队列或后台持续耗电；该次问题合理提示局限后返回正常本地主路径。
5. **如实说能力缺失**：本地没有对应地区/合格主故事则显示“尚无内容”、必要时用经审核的简短事实或安静；不能由旧事实假装完整主故事。GPS 弱/位置不新鲜则不可猜所在地；离线故事可看不等于未知位置也能自动附近播报。部分语音输入和更高质量 TTS 可能取决于设备是否安装有真正离线引擎，必须实测。
6. **知识生产与运行分离**：办公室/家里 AI 做资料与故事，GitHub 审核发布文字包，用户有网时才检查/下载安装；**驾驶途中正常播放完全不联系 GitHub，也不因暂时没更新而停播**。

**下一版本验收底线（分层做，不抢跑）**：在手机上事先安装新都合格讲述和离线中文 TTS，断开 Wi-Fi/移动数据、退出 ChatGPT 账号或令云端故意超时，**正常本地选题/讲述必须不等待任何云回应，云 Director/Research 调用=0**；在线恢复/失败均不破坏本地当前播放。真实 GPS 因手机现场限制取不到时按 PENDING 留待路测，先借“探索地点”实测断网文字+手动播放。不得把模拟 Location、Fake Provider 或单纯音色试听记作全部真实 GPS PASS。

## 本地原生运行主链：不等待云端模型

用户进一步确认：KITT 正常自动讲述不应先尝试 ChatGPT 再等待超时回退。默认离线优先时，按可信位置和已安装的 Fact/Narrative，依照六类兴趣、已播记忆与静音/冷却规则在本地选题，由设备的离线中文 TTS 直接播放。没有有效故事时可以安静；位置不可信不能猜测附近地点。

仅在用户提出需要在线的临时问题或明确选择“即时优先”模式时，才按实际可用的在线能力调用模型；普通问题若本地已有可靠知识，应先本地检索。在线故障只影响那一次在线任务，不得让“上次请求失败，等待下次触发”阻塞本地故事或文字浏览，也不可无限重试。

验收需分别测试无网络、无账号、代理不可用和在线请求超时。已有合格包及本地中文语音时，常规本地讲述不应产生云端模型请求；“探索地点”的异地浏览与手动播放不要求 GPS。真正自动沿途播报仍需可信真实 GPS，不能把模拟测试当真机定位验收。

这个决定是未来运行架构与验收标准，不代表 V0.4.0/code14 的独立讲述包和本地 Story Selector 已完成；仍按小版本授权施工。
